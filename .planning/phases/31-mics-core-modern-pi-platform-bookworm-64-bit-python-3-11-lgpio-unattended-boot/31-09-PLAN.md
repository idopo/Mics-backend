<objective>
Prove the phase goal's first sentence on real hardware: flash, clone, one script, reboot, and the
pilot comes up on its own.

Purpose: everything in plans 04-07 is currently a file that a test parsed. Parsing a unit file
proves the directive is present; it proves nothing about whether the unit starts, whether
`raspi-config nonint do_i2c 0` did what its source says it does on this kernel, whether the venv
resolves every pin to a wheel, or whether the hostname change survives a reboot. Those are
observations, and they need a boot.

**This plan also runs the pilot on Python 3.11 for the first time.** At this point the tree is
still pigpio-based (the lgpio port is plans 11-15), so the pilot needs `pigpio` present. That is a
deliberate intermediate state: it separates "does the OS/Python/installer work" from "does the GPIO
rewrite work", which is the whole reason the stage order is shed -> OS -> lgpio. Expect
`pigpiod` to be running here and to be purged in plan 16's re-provision.

Output: the provisioning section of the phase evidence log, with a verdict per PLAT id, plus
whatever corrections the real run forces back into the deploy scripts.
</objective>

<expected_friction>
Named in advance so a round trip is diagnosis, not surprise.

- **`Adafruit-PureIO` is sdist-only** (no wheels). It is pure Python so it should install without a
  compiler — but this is the one dependency that builds from source, and it is unverified. If it
  fails, that is a `requirements.txt` finding, not an installer bug.
- **The two `adafruit-circuitpython-*` lines are deliberately unpinned.** THIS is the "first fresh
  install" the requirements comment refers to. Resolve them here and write the pins back.
- **`gpiodetect` output is the ground truth for plan 11's chip resolver.** Capture it now while the
  card is in hand: `gpiodetect` and `gpioinfo | head -20`. Expect
  `gpiochip0 [pinctrl-bcm2711] (58 lines)` on a Pi 4 — note CONTEXT §5 said `pinctrl-bcm2835`,
  which is the Pi 2/3/Zero label. Record what the board actually reports.
- **The pilot may not reach a working state at all here.** It still needs `pigpio`, and the pilot's
  `external.start_pigpiod()` path may or may not behave on Bookworm. **This plan's gate is
  PROVISIONING, not a working pilot.** If the pilot starts, crashes on a pigpio problem, and
  systemd restarts it forever without latching, that is PLAT-09 PASSING. Record it that way and do
  not chase the pilot error here — plan 14 deletes that code.
- **`NetworkManager-wait-online`** is enabled by default on Bookworm, so `network-online.target` is
  meaningful. On a network-free boot it times out after a couple of minutes rather than hanging
  forever. If first boot is slow, check this before assuming a unit ordering bug.
</expected_friction>
