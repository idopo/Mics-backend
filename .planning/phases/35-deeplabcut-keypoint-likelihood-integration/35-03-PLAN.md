<objective>
Build `dlc-link-generate`: the one command that turns a researcher's trained-model configuration
into (a) the `ExternalHardware` subclass source they paste into the hardware-lib upload page and
(b) a machine-readable bodypart-to-signal-name map module the adapter IMPORTS.

Purpose: DLC-02 ("the declared keypoint set is STATIC in the lib's source — one lib version per
trained model") and DLC-13(b) ("a generator, not hand-authoring"). This is the core "generic way for
any lab member to link their model to the Pi" deliverable and the single largest build-from-research
file in the phase — no codegen precedent exists anywhere in this repository.

Output: a CLI that emits two paired files and hard-fails before emitting anything when the
declaration would be lethal at read time on the rig.
</objective>

<why_generation_time_validation_is_mandatory>
Each of these fails LATE and LETHALLY if not caught here (D-15):

- `stale_after_ms == 0` means NEVER STALE in `resolve_stale_value` (external_hardware_wire.py:141-156).
  It silently deletes DLC-05's entire occlusion semantic: a keypoint that stops updating keeps its
  last confident value forever and an FDA gated on it stays latched. There is no runtime symptom.
- `stale_policy` is validated at READ time and raises `ValueError` from inside FDA evaluation, on the
  rig, mid-run. The legal values are exactly `hold_last`, `return_default`, `return_none`. A typo is
  a run-killer.
- `ALLOWED_DTYPES` is enforced at CLASS-BUILD time by `resolve_dtype`: a `@signal` with neither a
  return annotation nor a typed default raises `TypeError` at lib import on the Pi. The backend's
  `api/extlink_ast.py:_signal_dtype` mirrors the same chain but deliberately does NOT raise, so a
  generator bug here fails SILENTLY at the AST layer (no signal offered in the editor picker) and
  loudly on the Pi much later.
- `return_none` on any signal a transition compares numerically is a task-killer:
  `FiniteDeterministicAutomaton.__next__` evaluates `all(expr() for expr in expr_list)` unguarded and
  `_build_transition_lambda` uses a raw `operator.gt`, so `None > 0.5` raises `TypeError` out of
  `__next__`.
</why_generation_time_validation_is_mandatory>
