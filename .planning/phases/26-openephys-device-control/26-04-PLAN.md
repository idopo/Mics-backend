```sql
SELECT session_id, pilot_id, started_at FROM session_runs WHERE id = :run_id
SELECT subject_id, protocol_id FROM subject_protocol_runs WHERE session_id = :sid ORDER BY id LIMIT 1
SELECT name FROM subjects WHERE id = :subject_id
SELECT p.name FROM projects p JOIN subject_projects sp ON sp.project_id = p.id
  WHERE sp.subject_id = :sid ORDER BY p.id            -- MANY-TO-MANY: may return >1
SELECT e.name FROM experiments e JOIN experiment_protocols ep ON ep.experiment_id = e.id
  WHERE ep.protocol_id = :pid ORDER BY e.id           -- MANY-TO-MANY: may return >1
SELECT name FROM pilots WHERE id = :pilot_id
```

  <files>api/artifact_paths.py</files>
  <behavior>
    - validate_template returns unknown token names and [] for a fully valid template
    - render_template raises UnknownTokenError naming every offending token
    - sanitize_segment turns `a/b c*` into one safe segment: no /, no whitespace, no shell-hostile chars
    - Every token in ARTIFACT_PATH_TOKENS is genuinely renderable
  </behavior>
  <action>
    Create the module. Its docstring must state, in the first paragraph, that this module is
    **device-agnostic** and that adding any device-specific knowledge to it is a defect — that
    statement is the human-readable half of the guard plan 26-01's `test_device_neutral_layer`
    enforces mechanically.

    - `ARTIFACT_PATH_TOKENS` and `DEFAULT_ARTIFACT_TEMPLATE` as declared above. **Note the default
  omits `{device}`**, so two artifact-producing devices on one pilot resolve to the identical
  `target_path` and `find_path_collision` will not flag it (same run). Harmless while OpenEphys is
  the only consumer; it will bite when DeepLabCut lands. Record the constraint in the docstring so
  whoever adds the second device sees it.
    - `validate_template(template)`: extract `{name}` occurrences with a single regex, return the
      sorted list of names not in `ARTIFACT_PATH_TOKENS`. An empty template is invalid — return a
      sentinel error rather than silently resolving to `""`; an empty path would send recordings to
      the device's own default location, which is the whole failure mode EPHYS-02 prevents.
    - `sanitize_segment(value)`: coerce to `str`, strip, replace any character outside
      `[A-Za-z0-9._-]` with `_`, collapse runs of `_`, strip leading/trailing `_` and `.`, and fall
      back to `UNRESOLVED_SEGMENT` when the result is empty. Never return `None`, never return a
      value containing `/`. **Sanitize per token value, not on the joined path** — sanitizing the
      whole rendered string would destroy the `/` separators the template author wrote deliberately.
    - `render_template(template, ctx, artifact_root)`: validate first, raise
      `UnknownTokenError(tokens)` if any unknown token is present, then substitute sanitized values.
      Collapse duplicate `/`.

      **The result is an ABSOLUTE path**, formed by joining the module-agnostic `artifact_root` from
      the device's `pilot_hardware_config.config` with the rendered relative template. Raise if
      `artifact_root` is missing or not absolute — do not silently produce a relative path.

      This is a pinned cross-plan contract, not a local choice. `target_path` is the ONE string
      three plans must agree on: `26-10` passes it verbatim as OE's `parent_directory`, and
      `26-08`'s backend force-stop establishes ownership by comparing the box's `parent_directory`
      against it. If the resolver emitted a relative path and the device prepended its own root,
      those two strings could never be equal, and the force-stop — the whole reason 26-08 exists —
      would silently return "not ours" on every invocation while still closing the artifact row. It
      also endangers EPHYS-02's "unambiguous across rigs": a relative `parent_directory` lands
      recordings wherever the OE process's cwd happens to be.

      `26-08` and `26-10` are both wave 3 and cannot read each other's summaries, so this must be
      settled here, in the plan text, rather than during execution.

    Keep this file under 300 lines (CLAUDE.md).
