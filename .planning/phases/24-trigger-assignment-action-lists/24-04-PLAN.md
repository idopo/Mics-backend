**1b — new method `_build_trigger_action_list`**, placed immediately after

```python
    def _build_trigger_action_list(self, trigger_name: str, actions: list):
        """
        Build ONE trigger callback that runs an ordered FDA action list.

        Deliberately thin: it delegates every action to _build_action_callable(), the SAME builder
        a state body uses. Nothing about specific hardware lives here. A new action type added to
        _build_action_callable (e.g. Phase 23's `compute`) therefore works inside a trigger with no
        change to this method.

        The returned callable explicitly declares `level` and `tick` because execute_trigger()
        dispatches on inspect.signature parameter NAMES (task.py:285-296). It stashes them on self
        so _resolve_arg({"trigger": ...}) can read them; process_queue() already holds
        self.trigger_lock across the whole execute_trigger() call, so this is safe without new
        locking.
        """
        action_callables = [self._build_action_callable(a) for a in actions]

        def _run_trigger_actions(level=None, tick=None,
                                 _callables=action_callables, _self=self):
            _self._trigger_level = level
            _self._trigger_tick  = tick
            for fn in _callables:
                fn()

        _run_trigger_actions.__name__ = f"trigger_actions_{trigger_name}"
        return _run_trigger_actions
```
The default-argument capture (`_callables=`, `_self=`) mirrors the convention in
`_build_action_callable` (lines 546/554/567) and the DNF transition builder (line 842), and prevents
the late-binding closure bug when several assignments are built in one loop.

Initialize `self._trigger_level = None` / `self._trigger_tick = None` in
`apply_trigger_assignments` before the loop, so a state-body action that mistakenly uses
`{"trigger": ...}` gets `None` rather than an `AttributeError`.
