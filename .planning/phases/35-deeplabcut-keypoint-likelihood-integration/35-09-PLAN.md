<what_this_plan_can_invalidate_downstream>
Plan 35-03's generator emits the same `liveness_hook` into every DLC lib by default, and plan 35-06
already generated and uploaded one carrying it. So this plan's verdict has a downstream consequence
that must be acted on, not just recorded:

- **If the hook works**, nothing changes; the generated DLC lib is correct as shipped.
- **If the hook FAILS on hardware** — `demo.alive` never goes true, or the readiness gate stalls —
  then the DLC lib carries a broken hook too. Plan **35-08** Task 1 is where that gets fixed, by
  regenerating with `--liveness-hook substrate-default` and re-uploading. Say so explicitly in the
  findings document so the next plan acts on it rather than inheriting it silently.
