<objective>
Stage 3, part 3, and the highest-risk change in the phase: the **output** half of `gpio.py`.

Purpose: `Digital_Out.store_series()`/`series()` are backed by pigpio **daemon scripts**
(`store_script` / `run_script` / `script_status` / `stop_script` / `delete_script`, with a
`PI_SCRIPT_INITING` polling loop). Those execute inside the C daemon, not in Python — which is why
valve-open duration is stable today. Four consumers depend on it, and the first one determines a
scientific quantity:

| Consumer | Why it matters |
|---|---|
| `Solenoid.open()` | valve open duration -> **reward volume** |
| `TTL` | sync pulse width — the cross-device alignment ground truth |
| `Pulse20Hz` | the LED stimulation train |
| `Digital_Out.blink` / `flash` | cue lights |

The replacement must be `tx_wave` (arbitrary sequences) and `tx_pulse` (uniform repeating trains).
**Never a Python `time.sleep`.** A sleep in the pulse path makes valve-open duration jitter under
load and reward volume variable — a data-quality defect, not an engineering one, and one that no
functional test would ever catch.

**The locked decision this plan exists to honour (CONTEXT §11.1).** `Pulse20Hz` is named for 20 Hz,
its code says `frequency = 60.0`, and the hardware emits **62.5 Hz** — because `_series_script`
does `str(round(dur))` against pigpio's integer-millisecond wait, turning 8.333 ms into **8 ms**,
period 16 ms. lgpio's microsecond resolution would "fix" that rounding to ~60 Hz and **silently
shift a stimulation parameter relative to every dataset collected so far**. The port must reproduce
**8000 us on / 8000 us off, bit-exactly**. A regression test asserting exactly that is mandatory,
not optional. Alongside: rename the class to reflect reality, and expose the frequency in prefs so
any future correction is a deliberate, dated change citable in a methods section.

Output: the pigpio script machinery deleted, the four consumers on `tx_wave`/`tx_pulse`, and the
62.5 Hz value locked by test.
</objective>

<verified_port_facts>
**Pattern A — one-shot / arbitrary sequence -> `tx_wave`.** Covers `Solenoid.open()` (the
reward-volume path) and any non-uniform `values[]`/`durations[]` sequence from `_series_script`.

```python
# lgpio.pulse(group_bits, group_mask, pulse_delay)  -- pulse_delay is MICROSECONDS
#   (lgpio_extra.py:169-185; the delay is added verbatim to the tx thread's next-edge
#    deadline in lgPthTx.c:136, so it is a true microsecond field)
# For a singleton output claimed with gpio_claim_output the group is one line: mask == 1.
pulses = [
    lgpio.pulse(level_on,  0b1, int(round(duration_ms * 1000))),
    lgpio.pulse(level_off, 0b1, 0),
]
lgpio.tx_wave(h, gpio, pulses)   # returns free queue slots; raises on TX_QUEUE_FULL
```
Two properties worth stating in code comments: `tx_wave` **copies** the pulse list into a malloc'd
buffer (`lgGpio.c:625-632`), so the Python list may be discarded immediately; and there is **no
maximum pulse count** within one wave — the only limit is **10 queued waves per GPIO**
(`LG_TX_BUF` == 10, `lgPthTx.h:36`). An arbitrary sequence of any length is one call.

**Pattern B — uniform repeating train -> `tx_pulse`.**
`tx_pulse(handle, gpio, on_us, off_us, offset_us, cycles)`; `cycles=0` means infinite.
Verified that **both** repeat-using consumers in the tree are uniform two-level cycles:
- `TTL.__init__`: `values=[on, off]`, `durations=[pulse_width, interval - pulse_width]`,
  `repeat=<n>`
- `Pulse20Hz._build_script`: `values=[on, off]`, `durations=[on_time, off_time]`, `repeat=-1`

so `cycles = repeat`, and `cycles = 0` for `repeat == -1`, covers both exactly. Stopping is
`tx_pulse(h, gpio, 0, 0, 0, 0)` — verified: "If both pulse_on and pulse_off are zero pulses will be
switched off for that GPIO. The active pulse, if any, will be stopped and any queued pulses will be
deleted."

**Two real gaps — state them, do not discover them:**
1. `tx_pulse` requires `on_us + off_us > lgMinTxDelay` (default **10 us**, `lgPthTx.c:34`), else
   `LG_BAD_PWM_MICROS`. Adjustable up to 1000 via `lgpio.set_internal(1, value)`
   (`LG_CFG_ID_MIN_DELAY == 1`). **No Python constant is exported — pass the literal `1`.**
2. There is **no lgpio primitive for infinitely repeating a NON-uniform wave.** `tx_wave` transmits
   a finite list and only 10 waves queue. Nothing in the tree needs it today. If a future FDA state
   wants a looping arbitrary pattern it needs a Python refill thread driven by
   `tx_room(h, gpio, lgpio.TX_WAVE)`, which reintroduces Python at the wave seams.
   **Record the constraint in the module docstring; do not pre-build the refill thread.**

**What disappears entirely, not ported:** `store_script`, `run_script`, `script_status`,
`stop_script`, `delete_script`, `PI_SCRIPT_RUNNING`, `PI_SCRIPT_INITING`, and the polling loop at
~`gpio.py:673-681`. `tx_wave`/`tx_pulse` enqueue **synchronously**, so the poll has nothing to
poll. The tree uses **no** `wave_*` pigpio calls today, only scripts — confirmed.

**The port should be a net REDUCTION in code.** Every pigpio-era workaround here — the script
store/run/status/delete dance, the `PI_SCRIPT_INITING` loop, the daemon-lifecycle code — exists
because pigpio is a separate process. Removing the daemon deletes the workarounds rather than
porting them. **If this file gets longer, something is being ported that should be deleted.**

**Pitfall 8 in its sharpest form.** `TX_QUEUE_FULL` is `-96` and lgpio raises. `Solenoid.open()` is
called from task logic and from callbacks. An exception escaping there unwinds the caller before its
remaining writes run. Catch `lgpio.error`, count it (follow the existing `_dropped_on_send`
pattern), log at the same 1/10/100/every-500 cadence the tree already uses, and never propagate.
A dropped reward that is **counted** is recoverable science; a dropped reward that raises mid-trial
is not.

**Pitfall 4 — fail-safe levels.** Chardev lines are released when the process dies, so a crash with
a solenoid energised reverts the pin to its default state. That is probably an improvement, but it
is a behaviour change **on the reward path** and must be verified per device physically (plan 16
V4). Add a `safe_level` concept to the output classes and a stop path that drives outputs there,
so plan 15's SIGINT handler has something to call.

**`pilot/test.py:27` also calls `.series()`** — a standalone test script, easy to miss (verified
2026-08-17: it is on line **27**, `led.series(id='hello', values=binary_letters,
durations=time_unit)`). Port it or delete it, and say which.
</verified_port_facts>
