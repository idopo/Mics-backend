<the_rule_that_outranks_every_other_goal_here>
**The viewer may never affect what the Pi receives.**

`DLCProcessor.process` runs synchronously on DLC's own inference thread, inside `get_pose()` — its
own docstring says a raise there stops inference on the researcher's machine mid-experiment. The
observer hook plan 38-01 added sits on that same thread. So:

1. Every viewer call on that thread is a **non-blocking put into a `LatestSlot`** and nothing else.
   No encoding, no drawing, no HTTP, no lock held for longer than a slot swap.
2. Encoding and drawing happen on the **viewer's own thread**, reading from that slot.
3. State polling happens on a **third thread** at ~1 Hz, so a two-second HTTP timeout cannot be felt
   anywhere near a frame.
4. Every exception anywhere in the viewer is caught, counted, and surfaced in the status block.
   `run_video_loop`'s `observer_errors` counter (plan 38-01) is the outer net; this is the inner one.

A viewer that drops frames is working correctly. A viewer that slows the sender is a defect.
</the_rule_that_outranks_every_other_goal_here>

Write `dlc_link/src/dlc_link/view_sinks.py`.

`NotebookSink` — imports `IPython.display` **inside** `__init__` and raises `SinkError` when it is
absent, with a message that names `--view-sink mjpeg` as the answer that requires installing
nothing. `update()` calls `clear_output(wait=True)` then displays the JPEG bytes (`IPython.display.Image`)
and the status lines. Every failure is caught and counted; the sink never raises into the caller.

`MjpegSink` — stdlib `http.server.ThreadingHTTPServer` on a thread, **bound to `127.0.0.1`** and
nothing else. State in the docstring, and in the printed startup line, that it is localhost-only,
that it serves frames and status text and nothing else, and that it writes no file. Two routes:
`/` (a minimal HTML page with the status lines and an `<img src="/stream">`) and `/stream`
(`multipart/x-mixed-replace; boundary=...`, writing the newest JPEG from the slot in a loop with a
small sleep). A client disconnect is a normal event: catch `BrokenPipeError` / `ConnectionResetError`,
count it, and carry on. `stop()` calls `shutdown()` and `server_close()` and is idempotent.

Both sinks read the newest JPEG from the viewer's output `LatestSlot`. Neither may block the viewer:
a sink that cannot keep up simply shows an older frame, and that is correct behaviour.

**Nothing in this module may install, suggest installing, or import at module scope, any package
outside the standard library.** `IPython` is imported lazily and its absence is a handled condition,
not a dependency. That is the whole reason the second sink exists (D-58/D-59): Jupyter pulls
`pyzmq`, and `RUNBOOK.md` step 2 already makes a proposed `pyzmq` change a STOP condition because
`mics-link`'s own transport is `pyzmq`.
