# Phase 2, Plan 1: Unified ElasticClient → tidy events DataFrame

**Phase goal:** One clean `ElasticClient` that fetches a session's behavioral events from Elasticsearch and returns a tidy, analysis-ready DataFrame — reading legacy and new-portal schemas through a single path, across configurable hosts/indices.

**Context:**
Legacy had two near-duplicate clients (`ElasticSearchClient.py` V1/V2, ~700 lines each) — the core patchiness. This is a clean rewrite: one client, one fetch path, the schema differences handled by nullable columns. Use the official `elasticsearch` Python client.

**Verified doc shape (live, `217/event_log_v2`, `m74_cue_reward` s4):**
```
_source: { pilot, subject, session, task_type, timestamp (ISO+tz), continuous,
           event: { event_type, event_data: {...}, level? } }
```
- `event.level` present for hardware events (1=on), ABSENT for `state_transition` and similar.
- `event.event_data.id` is the hardware id (`"OG_TRIGGER"`, `"TTL1"`, `"AUDIO1"`, or int for LICKER/IR); ABSENT for `state_transition`.
- LICKER/IR carry a `pi_timestamp` inside `event_data` (the on-Pi hardware time).
- Legacy docs (this fixture) have NO top-level `run_id` / `subjects`. New-portal docs add them.

**Depends on:** `ResolvedSession` (host, index, es_subject, es_session, run_id) from Plan 01-01.

## 1. `src/mics/elastic.py` — `ElasticClient`

```python
from elasticsearch import Elasticsearch
```

### Construction
- `ElasticClient(host: str = ES_PRIMARY)` → holds an `Elasticsearch([host])`. Cache clients per host (classmethod registry) so multiple sessions reuse connections.
- Helper `for_session(resolved) -> ElasticClient` picks the host from the resolved session.

### Query builder
`_build_query(es_subject, es_session=None, run_id=None, event_type=None)`:
- Always: `term subject.keyword = es_subject`.
- If `es_session is not None`: add `term session = es_session`. (Session-less path = omit it — ES-04.)
- If `run_id is not None`: add `term run_id = run_id` (new-portal filter; legacy fixture passes None).
- If `event_type`: add `term event.event_type.keyword = event_type`.
- Combine under `bool.must`.

### Fetch with scroll (ES-04)
`_scroll(index, query, page=1000) -> Iterator[hit]`: `search(scroll="2m")` then iterate `scroll()` until empty; clear scroll at end. (event counts are low-thousands but other sessions are larger — scroll is the safe default.)

### Public API
`fetch_events(resolved, event_type=None) -> pd.DataFrame`:
1. Build query from `resolved.es_subject`, `resolved.es_session`, `resolved.run_id`.
2. Scroll the resolved index, collect `_source` dicts.
3. Build rows via `_row(src)` (below) → DataFrame.
4. Sort by `raw_time`, compute `relative_time` (below), reset index.
5. Return DataFrame with stable column order:
   `["event_type","hardware_id","level","raw_time","relative_time","run_id","subjects","task_type","event_data"]`.

### Row mapping — `_row(src)`
| Column | Source | Notes |
|---|---|---|
| `event_type` | `src["event"]["event_type"]` | |
| `hardware_id` | `src["event"]["event_data"].get("id")` | nullable |
| `level` | `src["event"].get("level")` | nullable (None for state_transition) |
| `raw_time` | `pd.to_datetime(src["timestamp"])` | tz-aware |
| `run_id` | `src.get("run_id")` | None for legacy → ES-02 |
| `subjects` | `src.get("subjects")` | None for legacy |
| `task_type` | `src.get("task_type")` | |
| `event_data` | `src["event"]["event_data"]` | keep raw dict (duration, pi_timestamp, etc.) |
| `relative_time` | filled after sort | see below |

### relative_time
- Reference = the earliest `raw_time` in the returned set (session start). `relative_time = (raw_time - reference).dt.total_seconds()`, so the first event is 0.0.
- `aligned_time` is NOT computed here (Phase 4 adds it via the ephys trigger anchor). Leave the column out at this layer; the aligner adds it.
- Add a module docstring note: legacy `_get_relative_reference_time` keyed off the first trigger; we key off session start for a standalone events view, and the ephys-anchored `aligned_time` (Phase 4) is the cross-clock truth.
