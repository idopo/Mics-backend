<decisions>
## Decisions locked by this plan

1. **File schema.** CSV requires a header row with columns `t,signal,value` (extra columns are
   ignored, column order does not matter). JSONL is one JSON object per line with the same three
   keys. `t` is **seconds, float**, and only DIFFERENCES matter — the first row's `t` is the
   origin, so an absolute epoch, a relative offset, and a frame timestamp all work unchanged. This
   is what lets a DLC export be replayed without a conversion step (CONTEXT.md's "general usage").

2. **`value` typing.** JSONL gives native JSON types and is used as-is (subject to the SDK's own
   dtype rejection). CSV cells are strings, so they go through
   `mics_link.values.coerce_token(cell)` — the SAME function the driver uses, with
   `allow_json_dict=False`. Do NOT write a second token parser here.

3. **A malformed row is counted and skipped, never fatal** (CONTEXT.md, consistent with the Pi's
   EXTLINK-08 ingress philosophy). "Malformed" = missing column/key, unparseable `t`, empty
   `signal`, or unparseable JSON line. `read_rows` therefore takes a `ReplayStats` (or increments
   a passed-in counter) rather than raising — mirror the Pi's `DecodeStats`-by-reference shape.
   A file that is 100% malformed completes with `rows_malformed == N` and `sent == 0`; it does not
   raise and does not exit non-zero.

4. **Three timing modes, exactly as SDK-12 specifies:**
   - `realtime`: sleep so row *i* is sent at `t_i - t_0` seconds after start.
   - `scaled`: same, divided by `--scale` (`scale=2.0` means twice as fast; `scale=0.5` means half
     speed). Reject `scale <= 0` at argument-parse time.
   - `fast`: no sleeping at all.
   Timing uses `clock()` deltas against the ORIGIN, not cumulative per-row sleeps — cumulative
   sleeping drifts. If the sender falls behind schedule, do NOT sleep a negative amount and do NOT
   try to catch up by bursting; just send immediately and continue.

5. **NO latency, jitter, drift or achieved-rate-vs-target number is printed or asserted.** The
   final summary reports COUNTS only: rows read, rows malformed, sent, dropped, rejected, and
   wall-clock duration. Wall-clock duration is a duration, not a latency; do not label it or
   compare it to anything on the Pi. Phase 28 owns timing claims.

6. **`replay` takes a `link`, it does not create one.** `main()` creates the client via the public
   `connect(...)` and hands it in. This keeps `replay()` testable against `MicsLink(FakeTransport)`
   with no socket, and makes `replay()` reusable by Phase 35's adapter.

7. **`sleep` and `clock` are injected** (defaults `time.sleep` / `time.monotonic`) so the realtime
   and scaled modes are provable in milliseconds with a recording fake sleep — the tests must not
   actually wait.

8. **EVT replay is out of scope.** SDK-12 says `(t, signal, value)`. A `value` that parses as a
   dict is a malformed row here, not an event. Say so in the module docstring so nobody
   "improves" it later without a requirement.
</decisions>
