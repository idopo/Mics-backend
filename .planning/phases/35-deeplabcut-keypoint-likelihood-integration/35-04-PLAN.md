<objective>
Build the sender-side adapter (DLC-07): a `dlclive`-compatible `Processor` that pushes declared
signals into a `mics_link` client, and a standalone paced video-file loop that IS the live pipeline
with a file substituted for a camera.

Purpose: this is D-29's workflow A, the path proven FIRST at the rig. It is deliberately structured
so that swapping the prerecorded video for a live camera is dropping one line and nothing else.

Output: `dlc_link.signal_map`, `dlc_link.processor` and `dlc_link.live`, all unit-tested on a
machine with no dlclive, no cv2, no torch and no GPU.
</objective>

<three_rules_copied_verbatim>
From `sdk/examples/callback_sender.py` lines 1-20 - the load-bearing rules this plan applies:

1. The client is created OUTSIDE the callback and OUTLIVES it. The `with connect(...)` block owns
   the lifetime; the callback only borrows `link`. Here that means constructor injection: the caller
   builds `DLCProcessor(link, ...)` inside their own `with connect(...)` block and hands it to
   `DLCLive(...)`.
2. The callback returns whatever its host expects. `dlclive` assigns `self.pose` from
   `Processor.process`'s return value, so `process()` MUST return the pose.
3. Per-callback state (deadbands, last values) lives on the callback object, not in the SDK.

And: never open a client INSIDE a callback, and never rely on a library's teardown hook to close it.
`Processor.save()` is called by the DLC-Live GUI, not by `DLCLive`, so a client created in a
Processor's constructor may never be closed (D-32).
</three_rules_copied_verbatim>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| DLC inference thread -> mics_link IO thread | `send_signal` is called synchronously from DLC's inference thread once per frame, inside `get_pose()` and `_post_process_pose()`. SDK-15 exists for exactly this. |
| vision box -> Pi ROUTER on 5599 | Untrusted scalars cross the network into a device that actuates hardware. |
| generated map module -> `exec_module` on the sender | `load_signal_map` executes a Python file the researcher generated. |

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|

| T-35-15 | Denial of Service | Pi shared Tornado IOLoop and the STOP channel | mitigate | Every send passes the `Decimator` first, defaulting to the D-22 budget. `run_video_loop` paces at the video's native fps so the offline workflow cannot outrun the live case. |

| T-35-18 | Elevation of Privilege | `load_signal_map` executing a generated module | accept | The file is generated on the researcher's own machine by their own `dlc-link-generate` run and executed in their own process at their own privilege; it crosses no trust boundary.
