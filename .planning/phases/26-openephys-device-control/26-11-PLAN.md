<objective>
Close the loop: resolve each device's target path at run start, hand it to the device, record the
true final path the device reports back, and close the artifact when the run ends.

Purpose: the backend is the only party that can resolve a project/experiment/subject path — the Pi's
`run_ctx` carries a synthetic `subject_key` with no FK to `Subject` at all. So the backend resolves
and records the TARGET, the device produces and reports the RESOLVED path, and MICS ends up knowing
where its own data landed without a human transcribing anything.

**Everything here is device-neutral.** The endpoint, the ZMQ key, the handler and the close-on-stop
all speak in terms of `device_name`; DeepLabCut will use the identical path. This plan also carries
the per-run ephys opt-out, deliberately implemented on the existing `overrides` transport rather
than as a new mechanism.
Output: one endpoint, one api client trio, three small orchestrator changes.
</objective>

    - Each target is recorded in run_artifacts before the response is returned

    1. Resolves the run's `pilot_id` from `session_runs`.
