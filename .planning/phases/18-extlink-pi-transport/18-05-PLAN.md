  <action>
    Add `default_liveness`, `make_liveness`, `ROLE_ROUTER_BIND`, `ROLE_SUB_CONNECT`,
    `ROLE_NONE`, `socket_plan`, `requires_liveness_override`, `validate_role_liveness`,
    `identity_ok`, and `run_decoder`.

    **Liveness must be structurally independent of staleness (EXTLINK-07).** Do not implement
    `default_liveness` by calling `resolve_stale_value` or by sharing a cached timestamp with
    it. `alive` means *reachable/operational*; signal freshness stays entirely with the
    per-signal policy. A recording source with no spikes for 30s is alive with stale signals —
    if the two were coupled, a `stale_ms` generous enough for normal quiet periods would be
    minutes and `alive` would be useless as a failure detector. `make_liveness(predicate)` must
    REPLACE the default, never OR with it (OpenEphys overrides it to poll HTTP status, the only
    signal that distinguishes *rig off* from *rig quiet*).

    **`socket_plan` creates no socket and imports no zmq.** It returns a plain dict describing
    what plan 18-10's `.bind()` should do. Keeping it pure is what makes the role-selection row
    of the verification map agent-testable with a fake socket factory instead of a rig visit —
    and `sub_connect` is the ONE component in this phase with zero precedent anywhere in
    `autopilot/` (every existing socket binds a ROUTER or dials a DEALER to the orchestrator).

    **`run_decoder`'s contract (Claude's discretion per 18-CONTEXT, now being fixed):** the
    decoder receives the raw ZMQ frame parts as a list and may return a `dict` of
    `{name: value}`, a list of `(name, value)` pairs, or `None`. `run_decoder` normalizes that
    and routes EVERY produced `(name, value)` through the SAME declared-name check and dtype
    coercion `apply_envelope` uses — a foreign source gets no special dispensation to write an
    undeclared key or a wrongly-typed value into the View. Any exception raised inside the
    decoder is caught, counted as `malformed`, and returns `[]`; the decoder lives in a
    researcher-editable versioned lib, so it WILL raise eventually and must never take the
    IOLoop with it.

    **`ROLE_NONE` — the third role, control-only, NO inbound socket (EXTLINK-18).** Both
    other roles open a socket, so a device whose entire inbound story is an outbound poll —
    OpenEphys, whose liveness is an HTTP `GET /api/status` — would otherwise be forced to pick
    a port and bind a socket nothing ever connects to. `socket_plan` must therefore return a
    plan with `socket_type`, `action` and `endpoint` all `None`, `check_identity False`,
    `subscribe None`, `identity None`. Three hard rules, each pinned by a `-k role_none` test:
    it must NOT read or invent a port; it must NOT fall back to a default role; and an ABSENT
    `role` key stays a `ValueError` naming `role` — absent is not "none", because the explicit
    value is what lets preflight distinguish a deliberate control-only module from a forgotten
    field. Note in the docstring that `identity_ok` and the `@decoder` path are INAPPLICABLE in
    this role — there is no frame to check or decode — while everything else `.bind()` does
    (tracker registration, liveness, egress, lifecycle hooks) still happens in plan 18-10.

    **`requires_liveness_override` / `validate_role_liveness` — the rule that `role: "none"`
    REQUIRES an explicit liveness override (EXTLINK-18 + EXTLINK-07), pinned by the
    `-k role_none` tests.** `requires_liveness_override(role)` returns True for `ROLE_NONE`
    only, False for the two socketed roles, and raises `ValueError` naming an unknown role —
    same rule as `socket_plan`, so an unrecognised role can never slip through as "socketed, no
    override needed". `validate_role_liveness(role, has_override, class_name="")` returns None
    when the pairing is legal and otherwise raises `ValueError` naming BOTH the class and the
    role.

    Why it lives HERE rather than in `external_hardware.py`: the check is pure, so putting it
    in the `autopilot`-free module is the only way the agent can execute it — and it gives the
    rule exactly ONE definition. Plan 18-10's `ExternalHardware.__init__` CALLS
    `validate_role_liveness(...)`; it must not re-implement the condition. Take a plain
    `has_override` BOOLEAN, never a class or a hook object, so this module stays free of any
    knowledge of `ExternalHardware`.

    Why the rule exists at all (locked in 18-CONTEXT): the base default is "a message arrived
    within `stale_ms`", and a module with no inbound socket never receives one — it would sit
    permanently `alive=False` and, if `required`, hang the readiness gate until timeout with no
    useful diagnosis. Raising at construction mirrors EXTLINK-12's class-build-time `TypeError`:
    loud, immediate, before any data flows. A silent `alive=True` fallback is explicitly
    REJECTED — inventing liveness for a device we never poll is precisely the failure
    OpenEphys's HTTP status check exists to catch. Put that sentence in the docstring so nobody
    "helpfully" softens it later.

    Document at the top of `socket_plan` that in `sub_connect` there is no DEALER identity to
    check, so `source_id` survives purely as the tracker-name prefix — which is what keeps
    view-key naming (`oe.spike_rate`) identical across all three roles, `none` included.

    The third role adds a BRANCH plus two small pure functions, not a component, so the
    300-line budget should hold. **If it nonetheless pushes the file past 300, TRIM PROSE — do
    NOT split.** See Task 1: a split silently breaks the path-loading tests and nothing else,
    which is the worst possible failure mode. Trim the explanatory paragraphs down to their
    one-line core and keep every rule's "why" in a single sentence.
