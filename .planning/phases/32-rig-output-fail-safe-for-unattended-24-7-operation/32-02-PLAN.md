<objective>
Make `save_prefs()` crash-safe: write to a temp file in the destination's own directory, flush and
`fsync` it, then `os.replace()` over the destination.

Purpose: SAFE-04. `prefs.py:543` does `open(prefs_fn, 'w')` then `json.dump()` — truncate-then-write
in place, no temp-and-rename — and it runs on **every task start**, because
`_merge_prefs_hardware()` ends in `prefs.set("HARDWARE", ...)` and `Pilot.l_start` calls
`prefs.set('SUBJECT', ...)`. So the exact crash this phase exists to handle can leave the
fail-safe's own input half-written, AND leave the pilot unable to boot on the next start. Two
failures stacked in the one scenario the fail-safe exists for.

This is a pre-existing bug independent of the rest of the phase; it is in scope because SAFE-03
depends on the file it corrupts. The same tree already gets it right in
`deploy/render-prefs.sh:89,126` (`mktemp` + `mv`), with a comment saying an interrupted render
must never leave a half-written file. The shell script got it right; the Python that writes the
same file far more often did not.

Output: an atomic `save_prefs()` and a test that proves it by counting, not by inspection.

This plan is Wave 1 and depends on nothing — it does not need the discovery result.
</objective>

<!-- Current shape the executor is changing. Read the file; this is the contract summary. -->

`prefs.save_prefs(prefs_fn: str = None)` — when `prefs_fn` is None it resolves
`Path(get('BASEDIR')) / 'prefs.json'` and raises `RuntimeError` if `BASEDIR` is unset. It takes
the module-level `_LOCK` before writing. Under the `multiprocessing.Manager` path it dumps
`globals()['_PREFS']._getvalue()`, otherwise `globals()['_PREFS'].copy()`. `json.dump` is called
with `indent=4, separators=(',', ': ')` — both must be preserved byte-for-byte, because
`deploy/render-prefs.sh` and the install runbook both read this file by eye.

`prefs.set(key, val)` calls `save_prefs()` only when `_INITIALIZED` is true **and**
`'pytest' not in sys.modules`. That guard means a test can never exercise the write path through
`set()`; the test must call `save_prefs(prefs_fn=...)` directly with an explicit path.

`deploy/render-prefs.sh:89` uses `mktemp "${OUT}.XXXXXX"` — same directory as the destination, so
the later move is a same-filesystem rename. Copy that placement decision: a temp file in `/tmp`
would make `os.replace` a cross-device error on a Pi where `/tmp` is tmpfs.
</interfaces>
