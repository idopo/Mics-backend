<objective>
Close the lease loop: endpoints to acquire / force-release / reconcile, an orchestrator loop
that feeds reconciliation from the Redis heartbeat it already writes, and the frontend mirror so
a blocked researcher sees who holds the device.

Purpose: without release, the first lease acquired is permanent. `18-CONTEXT.md` assumed a
backend reconciliation already existed; research found `orchestrator_station.py::_run_watchdog`
is dead code (thread-start commented out) with a staleness rule that would kill every normal
multi-minute session. This plan BUILDS the replacement, keyed on the live `_redis_touch`
heartbeat, and adds the manual force-release for when reconciliation itself is wedged.
Output: leases that acquire, release, self-heal, and render.
</objective>

<task type="auto">
  <name>Task 2: Orchestrator — acquire on start, release on stop, reconcile on the Redis heartbeat</name>
  <files>orchestrator/orchestrator/orchestrator_station.py, orchestrator/orchestrator/mics/mics_api_client.py</files>
  <action>
    Add to `MicsApiClient`, using the existing `_get`/`_post`/`_delete` helpers:
    `acquire_device_lease(...)`, `release_device_leases_for_run(run_id)`,
    `reconcile_device_leases(heartbeats, stale_after_s=None)`, `list_device_leases()`.

    In `orchestrator_station.py`:

    1. **Acquire in `start_run`**, after `mark_run_running` succeeds. Derive the hosts from the
       dispatch spec's `PREFS_HARDWARE` block the orchestrator already builds — every config
       with a `role` key contributes its normalized `host`. That deliberately INCLUDES
       `role: "none"` control-only modules (EXTLINK-18): they open no inbound socket, but they
       still command one physical box, which is exactly what the lease arbitrates. Key off the
       presence of `role`, never off a port field. Wrap the whole acquire in
       `try/except` + `logger.warning`: preflight is the gate, so a failed acquire must NEVER
       block a run that preflight already cleared. Log loudly when `acquired` is False, naming
       the holder — that is the case where preflight was bypassed or raced.
    2. **Release in `stop_run`** (after `stop_session_run`) and in `on_task_error` (after
       `mark_run_error`), both in `try/except` — a failed release must not mask the real
       stop/error path. This is the clean-shutdown path; reconciliation is the safety net for
       everything else.
    3. **Add `_lease_reconcile_loop`** as a new daemon thread started in `__init__` alongside
       `_ping_loop`. Every 15 seconds it reads `updated_at` for every `pilot:*` hash in Redis,
       builds `{pilot_name: iso_ts}`, and POSTs it via `reconcile_device_leases`. The whole body
       is inside `try/except` + `logger.exception`, matching `_ping_loop`'s shape, so a Redis
       or API hiccup can never kill the thread.

       **Do NOT uncomment the `_run_watchdog` thread-start.** Leave that line and that method
       exactly as they are, and add a comment above the new loop explaining why: `_run_watchdog`
       keys on `active_run["started_at"]`, set once at `start_run()` and never refreshed, with an
       `elapsed > 30` threshold — re-enabling it would flag and error-out every behavioural
       session longer than 30 seconds. The new loop keys on `_redis_touch`'s `updated_at`, which
       is refreshed on every `on_state`/`on_ping` and is therefore a genuine liveness signal.
       Removing `_run_watchdog` is out of scope; misreading it as a working reconciliation is the
       documented trap.
    4. If `self.redis` is None (Redis unconfigured), the loop logs once and returns without
       spinning — the orchestrator must still boot without Redis.
  </action>
