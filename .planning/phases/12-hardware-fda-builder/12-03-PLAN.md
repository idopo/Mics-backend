# Phase 12, Plan 3: FDA Builder Bug Fixes

**Requirements:** HW-17, HW-18, HW-19, HW-20
**Phase goal:** Fix four usability bugs in the FDA builder discovered during Phase 12-01 implementation.

**Scope:** UI bug fixes + one API enhancement + one Pi change. No DB migrations.

**Gate:** Requires Phase 12-01 (StateBodyPanel, ActionEditor, ArgInput, TaskEditor all exist).

## Bug 1: Default action ref '' — methods not fetched on "Add Action"

**Root cause:** `DEFAULT_ACTION = { type: 'hardware', ref: '', method: 'set', args: [1] }` in `StateBodyPanel.tsx:5`. With `ref=''`, ActionEditor's `useEffect` calls `selectedHwModule()` which returns `undefined`, so `fetchMethods()` is never called. The method dropdown falls back to a plain text input showing `'set'`. Only after the user manually picks a different module does the fetch trigger.

**File:** `web_ui/react-src/src/components/StateBodyPanel.tsx`

In `addAction()` (~line 63), compute initial ref from first hw module attached to the toolkit:

```typescript
const addAction = () => {
  const toolkitModules = hwModules.filter(m => toolkit?.hardware_module_ids?.includes(m.id))
  const firstMod = toolkit?.is_backend_authored ? toolkitModules[0] : undefined
  const isTimer = firstMod?.lib_filename === 'timer.py'
  const initial: FdaAction = firstMod
    ? { type: isTimer ? 'timer' : 'hardware', ref: firstMod.name, method: '', args: [] }
    : { type: 'hardware', ref: '', method: '', args: [] }
  onChange({ ...state, entry_actions: [...actions, initial] })
}
```

Also remove the stale `DEFAULT_ACTION` constant at line 5 (no longer referenced).

## Bug 2: Bool arg select shows blank when stored value is 0 or 1

**Root cause:** `ArgInput.tsx:117` — `value={String(value)}`. When stored value is `1` (number, from `DEFAULT_ACTION` legacy), `String(1) = '1'` doesn't match `'true'` or `'false'`, so the `<select>` shows nothing.

**File:** `web_ui/react-src/src/components/ArgInput.tsx`

Change the bool select value to normalize numeric values:

```tsx
// line ~117:
value={value ? 'true' : 'false'}
```

This normalizes: `0 → 'false'`, `1 → 'true'`, `null → 'false'`, `true → 'true'`, `false → 'false'`.

**Note:** `Digital_Out.set(state: bool)` on the Pi accepts both `True`/`False` and `1`/`0` (Python coerces). If users want a numeric input instead of a checkbox, they should annotate the hw_lib param as `int`. No code change needed for that case — `int` annotation already produces a number input in ArgInput.

## Bug 3: Trial counter should be implicit — no dropdown selection needed

**Root cause:** The trial action type currently requires the user to select a Trial_Tracker flag from a dropdown. This is redundant — there should be exactly one `trial_counter` per toolkit, and it should just "increment" with no selection UI.

### Step 3a: API — auto-inject `trial_counter` flag

**File:** `api/routers/toolkits.py` — `_normalize_flags()` helper (near lines 50–80)

After normalizing existing flags, inject `trial_counter` if no Trial_Tracker exists:

```python
has_trial = any(v.get('tracker_type') == 'Trial_Tracker' for v in result.values())
if not has_trial:
    result['trial_counter'] = {'tracker_type': 'Trial_Tracker', 'initial_value': 0}
```

This ensures every toolkit returned by `GET /api/toolkits/{id}` has a `trial_counter` flag. Existing toolkits that already have a Trial_Tracker are unaffected.

### Step 3b: UI — show static label instead of dropdown

**File:** `web_ui/react-src/src/components/ActionEditor.tsx` — trial section (~lines 397–427)

When `trialFlagKeys.length === 1` (guaranteed after Step 3a), replace the dropdown with a static label:

```tsx
{trialFlagKeys.length === 1 ? (
  <div style={{ fontSize: '12px', fontFamily: 'monospace', color: 'var(--text)' }}>
    {trialFlagKeys[0]}
  </div>
) : trialFlagKeys.length > 1 ? (
  <select
    value={action.ref || trialFlagKeys[0]}
    onChange={e => onChange({ ...action, ref: e.target.value })}
    style={{ fontSize: '12px' }}
  >
    {trialFlagKeys.map(k => <option key={k} value={k}>{k}</option>)}
  </select>
) : (
  <input
    type="text"
    value={action.ref || ''}
    onChange={e => onChange({ ...action, ref: e.target.value })}
    placeholder="flag key"
    style={{ fontSize: '12px', width: '100%' }}
  />
)}
```

`handleTypeChange('trial')` already sets `ref: trialFlagKeys[0]`, which will now always be `'trial_counter'`. No change needed there.

### Step 3c: Pi — auto-create trial_counter if missing

**File:** `~/pi-mirror/autopilot/autopilot/tasks/mics_task.py` — `load_fda_from_json()`

After `self._semantic_hw` is built (~line 757) and before the state method building loop (~line 764), add:

```python
if 'trial_counter' not in self.flags:
    from autopilot.utils.Tracker import Trial_Tracker as _TT
    self.flags['trial_counter'] = _TT('trial_counter', 0, self.event_dispatcher)
```

This ensures backward compatibility: if a Pi receives a task definition referencing `trial_counter` but the toolkit's HANDSHAKE didn't include it (e.g., legacy toolkit or old Pi code), the tracker is created automatically.

## Bug 4: Newly created states lost after browser refresh (no auto-save)

**Root cause:** `TaskEditor.tsx` has no auto-save. The user must manually click "Save" after adding states. Changes to `fdaJson` in React state are lost on refresh if Save wasn't clicked.

**File:** `web_ui/react-src/src/pages/task-editor/TaskEditor.tsx`

Add a debounced auto-save that triggers 1500ms after `fdaJson` changes (only after initial canvas load):

```typescript
const autoSaveTimerRef = useRef<ReturnType<typeof setTimeout> | null>(null)

useEffect(() => {
  if (!fdaJson || !canvasInited) return
  if (autoSaveTimerRef.current) clearTimeout(autoSaveTimerRef.current)
  setSavedMsg('Unsaved…')
  autoSaveTimerRef.current = setTimeout(() => saveMutation.mutate(), 1500)
  return () => {
    if (autoSaveTimerRef.current) clearTimeout(autoSaveTimerRef.current)
  }
}, [fdaJson])
```

Keep the manual "Save" button as a secondary "Save now" option — useful when the user wants to force-save immediately without waiting for the debounce.
