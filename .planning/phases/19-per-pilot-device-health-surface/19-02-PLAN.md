    **`src/pages/index/deviceHealth.mts`:**

    ```ts
    /** One entry of a pilot's device_health map, keyed by full tracker name (e.g. "oe_ctl.alive"). */
    export interface DeviceHealthEntry {
      alive: boolean
      changed_at?: number | null   // epoch SECONDS, from the orchestrator's time.time()
    }

    export interface DeviceHealthWarning {
      deviceIds: string[]
      tooltip: string
    }

    /** The warning to show for a pilot, or null when there is nothing to say. */
    export function deviceHealthWarning(
      health: Record<string, DeviceHealthEntry> | null | undefined,
    ): DeviceHealthWarning | null
    ```

    Rules:
    - Report a device dead **only** on `entry.alive === false` — a strict identity check. A missing,
      null or non-boolean `alive` is *unknown*, and unknown must render nothing. A false alarm trains
      researchers to ignore the indicator, which is the exact failure HEALTH-05 exists to prevent;
      the same reasoning applies to a garbled payload.
    - `deviceIds` = keys with the trailing `.alive` stripped (only when present), **sorted**. Sorting
      matters: the WS replaces the whole payload every 0.5 s and JS object key order is not something
      to depend on for a string the user reads.
    - `tooltip` = one line per dead device: `${id} unreachable since ${localeTime}` when `changed_at`
      is a finite number, else `${id} unreachable`. Build `localeTime` as
      `new Date(changed_at * 1000).toLocaleTimeString()`. Join lines with a newline —
      `.state-warning-tooltip` sets `white-space: pre-wrap`, so newlines render.
      **Multiply by 1000**: the orchestrator sends seconds, `Date` takes milliseconds.
    - Return `null` when the dead list is empty. Never return a warning with an empty `deviceIds`.
    - **No device names anywhere in this file.** No `fetch`, no `stop`, no side effects at all — it is
      a pure function (HEALTH-06 is asserted against this mechanically below).

    **`tests/deviceHealth.test.mts`:** one `test(...)` per `<behavior>` bullet, in the style of
    `tests/trackerMethods.test.mts` (`import { test } from 'node:test'`,
    `import assert from 'node:assert/strict'`). Import from
    `'../src/pages/index/deviceHealth.mts'`. For the time-formatting case assert only that the
    tooltip *contains* the device id and the word `unreachable` and is longer than the no-time
    variant — do not pin a locale-formatted string, which would fail on a machine with a different
    locale or TZ.
