**1. What a trigger action list is.** One paragraph: a `trigger_assignments` entry may carry an

**2. Schema reference.** The five vocabulary additions this phase landed:

| Addition | Shape | Implemented in |
|---|---|---|
| `variables` registry | `"variables": {"name": {"initial_value": null}}` | `mics_task.load_fda_from_json` |
| `output` capture | `"output": "name"` or `["a","b"]` | `_build_action_callable` hardware/timer/method branches |
| `view` action | `{"type":"view","key_template":"…","value":…,"kwargs":{…}}` | `_build_action_callable` view branch |
| trigger context arg | `{"trigger": "level"｜"tick"}` | `_resolve_arg` |
| trigger `actions` | `trigger_assignments[*].actions` | `apply_trigger_assignments` → `_build_trigger_action_list` |

**3. The canonical lick-detection action list**, presented as the 1:1 translation of the removed
`detectedLick`, with a line-by-line mapping table (`pin_number, level = detect_change()` → the
`output` capture; `if pin_number is None: return` → the `if` action; `device_str =
f'{device_name}{pin_number}'` → `key_template`; `.set(level, pi_timestamp=tick)` → the `view`
action's `value` + `kwargs`):

```json
{
  "variables": { "pin_number": {}, "level": {} },
  "trigger_assignments": [
    {
      "trigger_name": "TOUCH_INT",
      "actions": [
        { "type": "hardware", "ref": "MPR121", "method": "detect_change",
          "args": [], "output": ["pin_number", "level"] },
        { "type": "if",
          "condition": { "left": {"flag": "pin_number"}, "op": "!=", "right": null },
          "then": [
            { "type": "view", "key_template": "LICKER{pin_number}",
              "value": {"flag": "level"},
              "kwargs": { "pi_timestamp": {"trigger": "tick"} } }
          ],
          "else": [] }
      ]
    }
  ]
}
```

State explicitly that the prefix is `LICKER`, not `MPR121`: `check_for_detectors` builds tracker keys
as `f"{detector.device_name}{i}"` and `prefs.json` sets `device_name: "LICKER"`, `num_detectors: 4`.

**4. Why the hardware returns a tuple.** Four electrodes share ONE `i2c.Touch_Detector` and ONE GPIO
interrupt (`TOUCH_INT`, pin 8). The interrupt says *something* was touched; the I2C query says
*which* electrode. The per-electrode abstraction is created in the view. This is deliberate
standardization — `hardware/i2c.py` is off-limits and `detect_change()`'s `(index, value)` return is
correct by design.
