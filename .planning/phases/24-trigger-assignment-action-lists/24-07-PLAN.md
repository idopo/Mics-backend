  <how-to-verify>
Three negative cases, each of which used to save silently and fail as a Pi `ValueError` minutes later
at session start.

1. **Unknown hardware ref.** In the editor, change the trigger action's hardware ref to a name that
   is not in the toolkit's semantic hardware. Save. Expect a **422** whose message names the trigger
   (`Trigger 'TOUCH_INT' action[0]: unknown hardware ref ...`) — NOT a silent 200 with a
   `broken` badge.
2. **Undeclared output slot.** Delete the `level` variable from the VARIABLES panel while the action
   still captures into it. Save. Expect a 422 naming `level`.
3. **Undeclared key template token.** Change the view action's key template to `LICKER{ghost}`.
   Save. Expect a 422 naming `ghost`.
4. **Empty trigger name.** Add an assignment and leave `trigger_name` blank. Save. Expect a 422.
   (Task definition 185 in the live DB holds two assignments in exactly this shape, saved through
   this panel before Plan 05 made the field required — so this is a real regression guard, not a
   hypothetical.)

Then confirm nothing regressed:
5. Restore a valid configuration and save. Expect 200.
6. Open a task definition with **no** trigger assignments at all (absent or `[]`). Make any trivial
   edit and save. Expect **200** — that is the backward compatibility that survives the reversal.
   There is no legacy `handler`-only case to check: the enum was deleted, and such an entry now 422s
   at the API and raises `ValueError` at Pi load.

Raw check if the UI swallows the error body:
```
curl -s -o /dev/null -w "%{http_code}\n" -X PUT localhost:8000/api/task-definitions/<id> \

  -d '{"fda_json": {"version":2,"initial_state":"s","states":{"s":{}},"transitions":[],
       "trigger_assignments":[{"trigger_name":"TOUCH_INT",
       "actions":[{"type":"hardware","ref":"NOPE","method":"detect_change"}]}]}}'
```

Empty `trigger_name` must also 422 — this is the shape task definition 185 actually holds in the
live DB today, saved through the UI:
```

       "trigger_assignments":[{"trigger_name":"","actions":[]}]}}'
```
