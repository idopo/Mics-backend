`pilot_hardware_config` row **21** on pilot 1 (`pilot_raspberry_lior`), `config` column, verbatim:

```json
{"class_name":"ExtlinkDemo","role":"router_bind","listen_port":5599,
 "host":"132.77.73.125","source_id":"demo","stale_ms":3000,
 "required":true,"wait_timeout_s":30,"egress_fail_threshold":3}
```

Field meanings the README must explain (the sender only needs three things):
- `source_id` — the DEALER identity the sender MUST use. A mismatch is dropped silently by the
  Pi's ROUTER with no NAK (EXTLINK-02). **The sender needs this.**
- `listen_port` — the port the Pi's ROUTER is bound on. **The sender needs this.**
- the pilot's own host/IP — **the sender needs this.** It is NOT the `host` field above; `host`
  is the module's *egress* target, a different thing entirely (see the warning below).
- `role: "router_bind"` — the Pi binds, the sender dials in. The only role the SDK supports.
- `stale_ms` — per-source liveness window. The sender does NOT need to know it; the SDK's default
  heartbeat is safe for any `stale_ms` at or above ~3s.
- `required` / `wait_timeout_s` — the readiness gate. A run on this pilot blocks up to
  `wait_timeout_s` and then FAILS if the source never connects.
- `host` / `egress_fail_threshold` — this particular demo module's OUTBOUND probe target. Nothing
  to do with the sender. Explain it only to stop the reader pointing their client at it.

The rest of the standing fixture: toolkit **100**, hardware module **62** (`ExtlinkDemo`), hardware
lib **177**, task definition **434** (`extlink_demo`), signals `left_paw_x` / `right_paw_x`
(`float`), event `object_detected`, plus the always-present `demo.alive` tracker. FDA transitions:
`wait -> armed` on `demo.left_paw_x > 0.5`, `armed -> fired` on `demo.left_paw_x < 0.2`,
`fired -> wait` unconditional, no terminal state.
</interfaces>

<decisions>
## Decisions locked by this plan

1. **Primary install line, documented first, verbatim:**
   `pip install "git+https://github.com/idopo/Mics-backend.git#subdirectory=sdk"`
   No credentials, no clone, no zip, no `PYTHONPATH`. Viable because `idopo/Mics-backend` is a
   PUBLIC GitHub repo (verified 2026-08-26; the remote is confirmed
   `https://github.com/idopo/Mics-backend.git`).

2. **The public-repo dependency is stated in the README, not left implicit.** If the repo is ever
   made private, this line breaks for every outside machine and each user needs a GitHub token.
   Write that down — a standing risk the user was told about deserves to be visible to the next
   person who hits it.

3. **Offline fallback is a built wheel**, `python -m build --wheel` from `sdk/`, documented as the
   no-internet path for a vision box on an isolated subnet. Build it and record the filename.

4. **PyPI is explicitly out of scope.** Do not write `pip install mics-link` anywhere as if it
   works. One sentence saying the public package name is a separate, deferred decision is correct;
   an aspirational install line is not.

5. **Ten lines is counted mechanically, not eyeballed.** The example lives in a real file
   (`sdk/examples/ten_line_sender.py`) so it is syntax-checked, and a test counts its non-blank,
   non-comment, non-docstring lines. The README embeds that same file's content. If the count
   exceeds 10, **fix the API, not the counter** — CONTEXT.md's explicit instruction and the
   phase's own usability test.

6. **The example must be ADDITIVE.** Three or four lines dropped into a loop the researcher
   already has (`for x in my_existing_loop():`) — never a restructuring, never a base class to
   inherit, never handing us their main loop. That is the north star from CONTEXT.md.

7. **The README is device-neutral.** No keypoints, no DeepLabCut, no pose arrays. The example
   signal name is `left_paw_x` because that is what the standing rig fixture declares, not because
   the SDK knows what a paw is. Phase 35 is a customer of this document, not a co-author of it.

8. **The README must repeat the identity warning** (34-RESEARCH.md Pitfall 5 / plan 34-06 decision
   8): `on_state_change(True)` means a TCP session exists, NOT that the Pi is accepting your
   `source_id`. A typo'd `source_id` produces a perfectly "connected" client whose every frame is
   silently discarded. This is the single most likely way a researcher wastes an afternoon.

9. **No latency, jitter or timing claim appears anywhere in the README**, and the "why there is no
   latency readout" reasoning is carried over from `tools/extlink_driver/README.md` (the two
   machines are not NTP-synced; Phase 28 owns that measurement).
</decisions>
