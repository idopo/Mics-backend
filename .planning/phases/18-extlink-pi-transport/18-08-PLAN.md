<objective>
Build the device lease's storage and its preflight gate: a lease keyed on the normalized `host`,
a `device_held` issue that names the holding pilot/subject/run, and an `extlink_config_invalid`
issue for the new config fields.

Purpose: one OpenEphys box has one record node and may be pointed at by several pilots' configs.
Two pilots issuing RECORD would clobber each other's session. The Pi cannot arbitrate this — it
does not know other pilots exist — so the backend does, using the existing preflight-as-gate
machinery: same response shape, same React renderer, zero new UI surface. Caught before the
animal is in the box, not after.
Output: a lease table, `api/device_lease.py`, and preflight step 10.
</objective>

Locked config schema for an external module (18-CONTEXT § Per-pilot config schema):
```json
{"class_name": "OpenEphys", "role": "sub_connect", "host": "132.77.x.x",
 "connect_port": 5556, "source_id": "oe", "stale_ms": 3000,
 "required": true, "wait_timeout_s": 60, "egress_fail_threshold": 3}
```
`listen_port` applies to `role: "router_bind"`; `connect_port` + `host` to `role: "sub_connect"`.
The third role, `"none"` (control-only, EXTLINK-18), requires NEITHER port — it opens no inbound
socket at all — but DOES require `host`, which is its egress target and its lease key.
`api/routers/pilot_hardware_config.py` stores config as-is and explicitly delegates validation
to the caller — so NO endpoint or schema change is needed for these fields. Their validation
belongs here, in preflight.
