    **`__init__`** absorbs the standard kwargs the base `init_hardware` passes

    - `kwargs.setdefault('type', self.__class__.__name__)` BEFORE `super().__init__(**kwargs)`.
      The base does a bare `kwargs['type']` and raises `KeyError` otherwise. This exact trap cost
      Phase 23 a debugging cycle — do not rediscover it.
    - `is_trigger = False` class attribute, so the base `init_hardware` skips `assign_cb`.
    - `get_state()` returns `None` — the `View.get_value` contract at `task.py:204` requires the
      method to exist on anything placed in the view.
    - `validate_wait_timeout(self.wait_timeout_s)` at construction, per EXTLINK-13's "`null`
      REJECTED at config save AND at Pi-side init".
    - Compute `socket_plan(config)` here, so a malformed config fails at construction — where
      `init_hardware`'s per-module `except` logs it clearly — instead of deep inside a callback.

    **`.bind(ioloop, view)`** — the one place needing real engineering care:
    ```python
    def bind(self, ioloop, view):
        ready = threading.Event()
        def _do_bind():
            # create the socket per self._plan, set identity (router_bind only), bind or connect,
            # SUBSCRIBE "" for SUB, wrap in ZMQStream(sock, ioloop), on_recv(self._on_recv)
            ready.set()
        ioloop.add_callback(_do_bind)
        if not ready.wait(timeout=5.0):
            raise RuntimeError("{}: bind timed out on shared IOLoop".format(self.name))
    ```
    **Never call `IOLoop.current()` inside this method.** `init_hardware()` runs in the thread
    `Pilot.run_task()` spawns, not the thread driving the loop; `IOLoop.current()` is thread-local
    and would silently construct a brand-new loop that nothing ever `.start()`s. No exception, no
    log — sockets appear created and `on_recv` never fires. `add_callback` is the only Tornado
    entry point documented as safe across threads. Put that reasoning in a comment.

    Register Trackers here: one per declared signal named `f"{source_id}.{signal_name}"`, seeded
    with the declared default, plus a `Boolean_Tracker` at `f"{source_id}.alive"`. Identical in
    both roles — in `sub_connect` there is no DEALER identity to check, so `source_id` survives
    purely as the tracker-name prefix, which is what keeps view keys uniform across roles.

    **`_on_recv(frames)` — the ingress firewall.** Stamp `ts_pi_recv` (canonical for FDA reads and
    CONTINUOUS logging; avoids NTP skew). For `router_bind`, drop frames whose DEALER identity
    fails `identity_ok`. Route through `run_decoder` when the class declares a `@decoder`,
    otherwise through `decode_envelope` + `apply_envelope`. Write each resulting update into its
    Tracker with `.set(...)` (already `@log_action`-decorated, so it reaches ES for free). Bound
    the incoming buffer with `collections.deque(maxlen=256)` — stdlib deque drops the oldest for
    free, matching the locked crash-isolation rule.
    **Wrap the ENTIRE body in a last-ditch try/except that logs and drops. Nothing may ever raise
    into the Tornado IOLoop** — that loop also serves every other module's ingress and the pilot's
    own orchestrator DEALER, so one traceback there takes the STOP channel down with it.
    Rate-limit the log to 1/sec per signal: the counters live in `DecodeStats`, the rate-limiting
    lives here, because the wire module is deliberately logger-free.

    **Egress:** construct one `EgressWorker` per instance with `fail_threshold` from config, an
    `on_drop` callback that emits a CONTINUOUS event NAMING what was lost, and an
    `on_alive_change` callback that flips the `alive` Tracker. Expose a public `send(item)` that
    enqueues and returns immediately — the FDA thread must never block on I/O, and neither must
    the IOLoop.

    **Liveness:** a `PeriodicCallback` at `stale_ms / 2` registered on the same ioloop
    re-evaluates the liveness callable (`make_liveness(self.liveness_hook)`) and applies each
    signal's `resolve_stale_value`. `alive` means REACHABLE, never data-fresh — a recording source
    with no activity for 30s is alive with stale signals. Every flip emits a CONTINUOUS event.
    Mid-run loss is logged and **never automatically fatal**: MICS does not kill a behavioural
    session because an accessory went quiet; the FDA author gates on
    `not view.get_value("<source_id>.alive")` if the experiment cares.

    **Lifecycle:** `on_run_start(run_ctx)` and `on_run_stop()` are no-op hooks subclasses
    override. `is_ready()` defaults to the current `alive` value — readiness is lib-defined and
    defaults to `alive` (EXTLINK-13 as amended).

    **`release()` — MANDATORY OVERRIDE.** The base raises
    `Exception('The release method was not overridden by the subclass!')`, and `Task.end()`'s
    per-object loop has NO try/except, so a missing override raises on EVERY run's teardown.
    `release()` must, in order and each step in its own try/except: call `on_run_stop()` exactly
    once (idempotent — guard with a flag), stop the `EgressWorker`, stop the PeriodicCallback,
    and close the ZMQStream/socket. It must NEVER raise. Mirror `timer.py::TIMER.release()`'s
    shape.

    **Do NOT rely on a CONTINUOUS event from inside `on_run_stop()` reaching ES.**
    `pilot.py::run_task`'s `finally` calls `event_dispatcher.stop()` BEFORE `task.end()`, so the
    sender thread may already have exited when `release()` runs. Use a plain `self.logger` call
    for stop-time evidence — that always reaches the Pi's local log file. Put this in a comment
    so no later phase writes an untestable acceptance criterion on it.

    Import `zmq` / `ZMQStream` / `PeriodicCallback` at module scope alongside the `autopilot`
    imports — this file is already USER-RUN, so there is nothing left to protect here. **But do
    not move any pure logic out of the two sibling modules into this file** to "simplify"; that
    would convert the phase's entire agent-side test suite into rig work.

    Budget: <= 300 lines. If it would exceed that, split the ingress firewall into
    `external_hardware_ingress.py` (which MAY import `autopilot`) rather than letting the file
    grow, and record the split in the SUMMARY.
