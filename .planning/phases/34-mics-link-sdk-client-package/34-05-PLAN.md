<objective>
Retire the proof-of-concept driver outright. Delete `extlink_wire.py`, `extlink_driver.py` and
`test_extlink_wire.py`; keep `extlink_demo_fda.json` and a rewritten `README.md`.

Purpose: SDK-10 — *"exactly one sender-side wire implementation exists when this phase ends."*
Two hand-written implementations of one envelope is the drift Phase 18 already produced once.

**Scope decision (user, 2026-08-26):** the driver was a proof of concept. It is not being ported
to the SDK — it is being removed. The SDK supersedes it, `sdk/examples/` carries the worked
senders, and the real integration proof is Phase 35's DLC work. Deleting satisfies SDK-10 more
cheaply and more honestly than maintaining a POC's CLI surface.

**What is deliberately NOT deleted:** `extlink_demo_fda.json` is a rig fixture, not driver code,
and the README holds rig facts that plans 34-08 and 34-09 cite by @-reference. Removing either
would break downstream plans. Delete the code; keep the knowledge.
</objective>

<decisions>
1. **Delete the code, keep the fixture and the doc.** `extlink_demo_fda.json` is referenced by the
   34-09 rig checkpoint; `README.md` is @-referenced by 34-08 (tone/structure precedent for the SDK
   README) and 34-09 (rig prerequisites). The directory survives with two files.

2. **`test_extlink_wire.py` goes with the module it tests.** It imports `extlink_wire` at module
   scope; leaving it would break collection for the whole repo. Its patterns already live on in
   `sdk/tests/test_wire_parity.py` and `sdk/tests/test_import_hygiene.py` (34-01).

3. **No `extlink_cli.py`, no retargeted driver.** The superseded plan created a CLI shim to keep
   the driver alive. That work is cancelled — nothing imports it.

4. **`extlink_driver_mac.zip` at the repo root is NOT deleted by this plan.** It is untracked and
   belongs to the user. This plan only notes it as stale in the README, because it bundles a copy
   of the very module being deleted. Deleting a user's untracked file is not this plan's call.

5. **Downstream verify commands must stop running the driver's test suite.** After this plan,
   `python3 -m pytest -q tools/extlink_driver/` collects zero tests and pytest exits **5**, which
   reads as a failure. Plans 34-06, 34-07, 34-08 and 34-09 each carry such a step and each is
   corrected to assert absence instead. This plan's Task 2 verifies that correction landed.
</decisions>
