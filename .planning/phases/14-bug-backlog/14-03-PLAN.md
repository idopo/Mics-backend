# Phase 14, Plan 3: Toolkit Creation Modal UX Fixes

**Requirements:** BUG-05, BUG-06, BUG-07  
**Phase goal:** Fix three bugs in the New Backend Toolkit creation modal — a useless dead step, a redundant hw-lib selection step that should be automatic, and a 404 proxy gap that blocks toolkit creation when hardware libs exist.

---

## BUG-07: POST /api/toolkits/{id}/hardware-libs returns 404

### Root cause

`web_ui/app.py` has individual proxy routes for four specific toolkit paths:
- `GET /api/toolkits`
- `POST /api/toolkits`
- `PATCH /api/toolkits/{toolkit_id}`
- `GET /api/toolkits/by-name/{name}`

There is no proxy route for `POST /api/toolkits/{toolkit_id}/hardware-libs` or the related `GET` and `DELETE` variants. The actual API endpoint exists in `api/routers/hardware_libs.py` (registered at app startup via `app.include_router(hardware_libs_router, prefix="/api")`), but the web_ui proxy at `:8080` never forwards the request — it falls through to the FastAPI catch-all and returns 404.

### Fix

**File:** `web_ui/app.py`

Add wildcard proxy routes for the toolkit↔hardware-lib link sub-resource, immediately after the existing `proxy_toolkits_by_name` route (around line 425):

```python
@app.api_route("/api/toolkits/{toolkit_id}/hardware-libs", methods=["GET", "POST"])
async def proxy_toolkit_hw_libs(toolkit_id: int, request: Request):
    body = await request.body()
    async with backend_client() as client:
        resp = await client.request(
            method=request.method,
            url=f"{API_URL}/api/toolkits/{toolkit_id}/hardware-libs",
            content=body,
            headers={"Content-Type": "application/json"} if body else {},
        )
    return FastAPIResponse(content=resp.content, status_code=resp.status_code,
                           media_type=resp.headers.get("content-type", "application/json"))


@app.api_route("/api/toolkits/{toolkit_id}/hardware-libs/{lib_id}", methods=["GET", "DELETE"])
async def proxy_toolkit_hw_lib_item(toolkit_id: int, lib_id: int, request: Request):
    async with backend_client() as client:
        resp = await client.request(
            method=request.method,
            url=f"{API_URL}/api/toolkits/{toolkit_id}/hardware-libs/{lib_id}",
        )
    return FastAPIResponse(content=resp.content, status_code=resp.status_code,
                           media_type=resp.headers.get("content-type", "application/json"))
```

### Verification

```bash
# Create a toolkit, then:
curl -s -X POST http://localhost:8080/api/toolkits/1/hardware-libs \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $TOKEN" \
  -d '{"hardware_lib_id": 1, "version_id": null}'
# Should return 200, not 404
```

## BUG-05: Step 2 is a dead screen when no source file is selected

### Symptom

When the user leaves the source file dropdown at "— none (base mics_task) —" and clicks Next in step 1, they land on step 2 which shows only:

> "No task source file selected — toolkit will run the base mics_task class with no locked states."

This is a dead end — there is nothing to interact with, just an info message. The user must click Next again to continue. The same message is visible in step 1 implicitly (selecting "— none —" is already the default). This step adds no value when no file is selected.

### Fix

**File:** `web_ui/react-src/src/pages/toolkits/CreationModal.tsx`

Change the wizard step navigation so that step 2 (locked-states selector) is skipped entirely when `!selectedFile`. Apply this in both the Next and Back direction:

```typescript
// Replace the generic step handlers in modal-actions with direction-aware logic:
const handleNext = () => {
  if (step === 1 && !selectedFile) {
    setStep(3)  // skip locked-states step
  } else {
    setStep(s => s + 1)
  }
}

const handleBack = () => {
  if (step === 3 && !selectedFile) {
    setStep(1)  // skip back over locked-states step
  } else {
    setStep(s => s - 1)
  }
}
```

Update the modal footer to call `handleNext` / `handleBack` instead of inline lambdas.

Update the modal header title to reflect the effective step count:

```typescript
const effectiveStepCount = selectedFile ? 5 : 4
// For display, map internal step number to visible position:
const visibleStep = (step > 2 && !selectedFile) ? step - 1 : step
// Header: `New Backend Toolkit — Step {visibleStep} of {effectiveStepCount}`
```

> Note: The title only changes after step 1 (where the file choice is visible), so the "Step 1 of N" display on landing should show 5 as a default and only adjust when the user has committed to no-file and moved forward.

Simplest acceptable alternative: keep the header as "Step {step} of 6" and do not update it — the skip is UX enough. Match what feels clean to the implementer.

### Verification

1. Open New Toolkit modal, leave source file as "— none —", click Next.
2. Should land directly on the hw-modules step (old step 4), not the "no file" info screen.
3. Click Back from hw-modules — should return to step 1 (name+file).
4. Select a source file. Click Next.
5. Should land on the locked-states selector (step 2 content shows checkboxes).
6. Click Back — returns to step 1.

## BUG-06: Step 3 (hardware lib selection) is redundant — auto-link all

### Symptom

Step 3 asks the user to manually select which hardware libraries to link and which version to pin. But the correct behavior is: **always link all libraries**, using the stable version if one is marked, or the latest active version otherwise. Manual selection adds friction with no benefit — there are very few libs and the defaults are always the right choice at creation time. (Version pinning can be adjusted per task-definition later in the FDA editor.)

### Fix

**File:** `web_ui/react-src/src/pages/toolkits/CreationModal.tsx`

1. **Remove step 3 entirely** — delete the `{step === 3 && ...}` block.

2. **Remove related state and helpers** — delete:
   - `selectedLibVersions` state
   - `libVersionCache` state
   - `toggleLib` function

3. **Renumber remaining steps**: old step 4 → 3, old step 5 → 4, old step 6 → 5. Update all `step === N` guards, the `canNext1` / footer disabled checks, and the step count in the modal title (`"Step {step} of 5"`).

4. **Update the skip logic in BUG-05** to account for the new step numbers (step 2 = locked states, step 3 = hw-modules, step 4 = flags, step 5 = params). The skip now jumps from step 1 → step 3 and step 3 → step 1.

5. **Auto-link in `onSuccess`**: Replace the `selectedLibVersions` loop with a loop over all `hwLibs`:

```typescript
onSuccess: async (toolkit) => {
  if (hwLibs.length > 0) {
    await Promise.all(
      hwLibs.map(lib =>
        linkLib(toolkit.id, lib.id, lib.stable_version_id ?? lib.active_version_id ?? null)
      )
    )
  }
  onCreated()
},
```

`hwLibs` is already fetched via `useQuery(['hardware-libs'], listHardwareLibs)` — no new fetch needed.

6. **Remove `listVersions` import** from the import line (no longer called in this file). Keep `linkLib`.

### Verification

1. Open New Toolkit modal. Verify there is no hardware libs selection step — the wizard now has 5 steps (4 when no file selected).
2. Fill name, skip file, click through to Create.
3. After creation: call `GET /api/toolkits/{id}/hardware-libs` — should return all existing libs linked with their stable/active version.
4. If no hardware libs exist, creation completes without error (empty `hwLibs` → `Promise.all([])` → resolves immediately).
