<objective>
Make `dlc-link-live` open a camera, pace correctly for one, count what it cannot keep up with, and
stop deliberately. This is the plan that turns a proven file-driven pipeline into a proven
camera-driven one; everything downstream of the frame source is already proven by Phase 35 runs 587
and 588 and is not touched here.

Purpose: CAM-01 through CAM-04. The researcher's camera is being installed for the week of
2026-09-08 and this is the plan that has to be finished for that week to be usable at all.

Output: three new pure/injectable modules (`source`, `latest`, `capture`), a `live.py` reduced to
the loop plus its pure helpers, a new `live_cli.py` holding the CLI, and tests that run on the dev
host with no cv2, no dlclive, no camera and no GPU.
</objective>

<decisions_this_plan_implements>
`38-DECISIONS.md` D-49 (one `--source`, `--video` as an alias), D-51 (pacing is a property of the
source), D-52 (reader thread + `LatestSlot`, overwrites are the keep-up count), D-53
(`behind_count` is `n/a` when unpaced), D-54 (`--min-rate` has no default; `--capture-only`
supplies the baseline), D-55 (four deliberate stops; bounded retry for a camera, first-failure stop
for a file), D-61 (no hardcoded row count).

Read that file before starting. It contains the reasoning; this plan contains the work.
</decisions_this_plan_implements>

Write `dlc_link/src/dlc_link/latest.py`:

`LatestSlot` — a single-slot, drop-oldest holder guarded by a `threading.Lock`. `put(item)` replaces
whatever is there, incrementing `overwrites` when it replaced an untaken item. `take()` returns
`(True, item)` / `(False, None)`. Counters: `puts`, `takes`, `overwrites`. `snapshot()` returns
those three and nothing else — the DLC-10 rule from `decimate.py` applies here verbatim and the
module must carry a comment saying so: no field may be added whose name or value could be read as a
latency, jitter or drift figure.

The docstring must state, in its own words, why `overwrites` is the number that matters:
**`overwrites` IS the count of frames the pipeline could not service.** With a file that number is
zero by construction; with a camera it is the honest keep-up instrument, and it exists because
`behind_count` cannot be one for an unpaced source (D-53).

Two consumers, stated in the docstring so nobody adds a third mechanism later: the camera reader
(this plan) and the viewer tap (plan 38-03).

Write `dlc_link/src/dlc_link/capture.py`:

`FrameReader` — a `threading.Thread` wrapper. **`cv2` is not imported here.** The constructor takes
a `read` callable (in production `cap.read`; in tests a fake returning queued `(ok, frame)` pairs), a
`LatestSlot`, `terminal_on_failure: bool` (from `source.read_failure_is_terminal`), `read_retries`,
and an injected `sleep` (default `time.sleep`) so tests never wait for real.

Loop: call `read()`. On `ok`, `slot.put(frame)` and reset the consecutive-failure count. On not-`ok`
with `terminal_on_failure` -> stop, `stopped_reason = "end-of-stream"`. On not-`ok` otherwise ->
increment the consecutive-failure count, `sleep(retry_interval_s)`, and stop with
`stopped_reason = "read-failures-exhausted"` once it reaches `read_retries`. A `stop()` call sets a
flag the loop checks each iteration; `stopped_reason` becomes `"stopped"`. Any exception out of
`read()` is caught, counted as `read_exceptions`, and treated as a failed read — a driver hiccup
must not kill the thread silently and leave the main loop waiting forever.

`snapshot()`: `frames_read`, `read_failures`, `read_exceptions`, `stopped_reason`, plus the slot's
own snapshot nested under `slot`. Counts and one reason string. Nothing else.

`FrameReader` never calls `release()`, never touches the link, and never raises out of `run()`.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| camera / network stream -> `cv2.VideoCapture` -> inference -> ZMQ -> pilot | An uncontrolled frame source now drives a device that actuates hardware in an animal's cage. Previously this input was a file the researcher chose. |
| reader thread -> inference thread | A second thread now exists inside the sender process; a fault there must not deadlock or silently starve the loop that feeds the Pi. |
| CLI arguments -> `cv2.VideoCapture` | A string argument selects between a local device, a network URL and a filesystem path. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-38-01 | Spoofing | a stream URL pointed at the wrong camera, or a device index that is the laptop webcam rather than the rig camera | mitigate | `SourceSpec.describe()` is printed before the capture is constructed, and the viewer (plan 38-03) shows the frames — a wrong source becomes visible in one glance instead of producing plausible-looking keypoints from the wrong scene. This is the frame-source analogue of `--port`'s no-default rule (a wrong-but-open port reaches a live fixture). |
| T-38-02 | Tampering | buffered stale frames presented to the FDA as current | mitigate | `LatestSlot` drop-oldest plus `CAP_PROP_BUFFERSIZE=1`; the dropped count is reported as `frames_skipped`. The Pi's `stale_ms: 3000` cannot see this failure — the data keeps arriving, it is just old — so it must be handled at the source. |
| T-38-03 | Denial of Service | a camera faster than the model, starving the loop | mitigate | Frames are dropped by design (drop-oldest) rather than queued; the outbound rate is unchanged because the decimator's per-signal Hz cap governs the wire, not the frame rate. `--min-rate` makes the shortfall an explicit non-zero exit rather than a number nobody read. |
| T-38-04 | Denial of Service | a camera that stops delivering mid-session, hanging the loop forever | mitigate | `FrameReader` bounds consecutive failures with `--read-retries` and records `stopped_reason`; the loop ends and the summary says why. Separately the Pi's `stale_ms: 3000` returns declared defaults, which is the fail-safe that already exists downstream. |
| T-38-05 | Denial of Service | `cap.release()` racing the reader thread | mitigate | `FrameReader.stop()` is called in the `finally`, before `cap.release()`, and `stop()` is idempotent and tested as such. |
| T-38-06 | Repudiation | a camera run reporting `behind_count: 0` and being read as "kept up" | mitigate | D-53: an unpaced run prints `n/a (unpaced source)`, never `0`, and prints `frames_skipped` instead. Enforced by an `is None` assertion in the tests. |
| T-38-07 | Information Disclosure | an RTSP URL with embedded credentials printed into a terminal or a summary | accept | The researcher types the URL; echoing what they typed is how they confirm it was read correctly (T-38-01), and this tool writes nothing to disk, so the exposure is the terminal they are already looking at. Named so the choice is deliberate; if credentialed URLs become normal, redacting the userinfo component is the fix. |
| T-38-08 | Elevation of Privilege | a malicious network stream exploiting a codec in the OpenCV/FFmpeg stack | accept | The camera is on the lab network and is the researcher's own; the same codec path already processed their video files in Phase 35.
