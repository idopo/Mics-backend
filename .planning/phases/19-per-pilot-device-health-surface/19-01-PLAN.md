`.alive` tracker suffix and on nothing else.

it into Elasticsearch and forgets it. This plan gives it a second, live destination that costs one
dict write on the IOLoop thread.

<interfaces>
Verified by direct read on 2026-08-05.

**The wire payload.** `main.py:75-77` maps `DATA`, `CONTINUOUS` and `STREAM` all to `station.on_data`.
`RouterGateway._on_recv` sets `msg.sender` from the ROUTER identity frame — its own docstring calls
that "the authoritative sender", and `on_handshake`/`on_state`/`on_ping` all key state and Redis off
the same value. `msg.value` is built by the Pi's `Event_Dispatcher._sender_loop`
(`~/pi-mirror/autopilot/autopilot/networking/Event_Dispatcher.py:38-50`):

```python
{"pilot": ..., "subject": "bp_s<session>_r<run>", "session": ..., "run_id": ...,
 "task_type": ..., "timestamp": ..., "continuous": True, "session_progress_index": ...,
 "subjects": [...],
 "event": {"event_type": "Boolean_Tracker",
           "event_data": {"id": "oe_ctl.alive", "value": 0, "result": None, "func_name": "set"}}}
```

**The tracker name lives at `value["event"]["event_data"]["id"]`.** That is the full view key,
`f"{source_id}.alive"` (Phase 18 plan 18-10 registers it as a `Boolean_Tracker` under exactly that
name).

**`alive` arrives as an int, NOT a bool — this is load-bearing and is not in the research doc.**
`log_action` (`~/pi-mirror/autopilot/autopilot/utils/logging_utils.py:41`) runs every tracker value
through `coerce_for_event`, and `log_value.py:69-71` maps a raw bool to `int(raw)` because
`event.event_data.value` is mapped `long` in `event_log_v2` and a long field **rejects a bare bool
with an HTTP 400**. So a `False` flip arrives as `"value": 0`. Parse truthiness from the number; do
not `isinstance(raw, bool)` and give up.

Also note `Boolean_Tracker.set` is `@log_action`-decorated *and* calls an `@log_action`-decorated
`super().set`, so one flip emits the same event **twice**. Idempotent here — the second write is a
no-op because the value did not change — but do not be surprised by it in the logs.

**`msg.value` shapes to survive without raising:** `None` (signal-type messages), a non-dict, a dict
with no `event`, an `event` with no `event_data`, an `event_data` with no `id`, and an `id` that is
not a string. All must return quietly.

**`set_active_run` call sites:** `orchestrator_station.py` lines 369, 429, 442, 477, 486, 611, 976
pass `None`; line 390 passes a run dict. Do not touch any of them.

    ```python
    def set_device_health(self, pilot: str, tracker: str, alive: bool) -> bool:
        """Record a device liveness level. Returns True only if the level CHANGED."""
        with self._lock:
            cur = self._device_health.setdefault(pilot, {})
            prev = cur.get(tracker)
            if prev is not None and prev.get("alive") == alive:
                return False
            cur[tracker] = {"alive": alive, "changed_at": time.time()}
            return True

    def get_device_health(self, pilot: str) -> dict:
        with self._lock:
            return {k: dict(v) for k, v in self._device_health.get(pilot, {}).items()}
    ```

    IOLoop thread may be writing. `changed_at` is `time.time()` (epoch seconds, JSON-safe) and is

    pilot the orchestrator has never handshaked is meaningless, and `snapshot()` iterates `_pilots`,
    so unsolicited traffic can never invent a pilot card.
