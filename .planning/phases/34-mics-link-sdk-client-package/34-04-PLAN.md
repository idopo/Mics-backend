ACK_OK    = "ok"       # key names used in the result dict below

<decisions>
## Decisions locked by this plan

1. **ACK `result` shape is a dict, locked here so Phase 35 and any future Pi-side consumer can
   rely on it:**
   - success: `{"ok": True, "value": <handler return>}`
   - handler raised: `{"ok": False, "error": "<ExcType>: <message>"}`
   - no handler registered: `{"ok": False, "error": "unknown command: <name>"}`
   - handler returned something msgpack cannot pack:
     `{"ok": False, "error": "unencodable result: <ExcType>: <message>"}`
   A handler returning `None` is a success with `"value": None` — that is the normal shape for a
   fire-and-forget command.

2. **`dispatch` never raises. Ever.** It catches `BaseException` from the handler? No — catch
   `Exception`. `KeyboardInterrupt`/`SystemExit` must still propagate so a Ctrl-C in the
   researcher's program still works. Say this in a comment; it is a deliberate narrowing, not an
   oversight.

3. **Encoding the ACK is itself inside the try.** A handler returning a numpy array or a socket
   object would blow up in `msgpack.packb`, not in the handler. That failure must still produce a
   valid error ACK, not an exception on the worker thread — hence the "unencodable result" case in
   decision 1. This is the case a naive implementation misses.

4. **Handlers run on ONE dedicated thread, not the IO thread.** A slow or hanging
   researcher-supplied handler would otherwise stall heartbeats, reconnect detection and outbound
   draining all at once (34-RESEARCH.md Pattern 5). One thread is sufficient — SDK-08 requires
   isolation, not concurrency. Commands are therefore serialized, which is the right default for a
   control channel; document it.

5. **The worker's inbox is bounded and drops the NEWEST on overflow**, same policy and same reason
   as `BoundedSender` (SDK-06 / EXTLINK-15). A flood of commands must not grow memory without
   bound. Default `maxsize=32` — commands are a control channel, not a data stream.

6. **Duplicate registration is a programmer error** and raises `MicsLinkError` at registration
   time. Silently replacing a handler is the kind of thing that surfaces at 3 a.m.

7. **`ts_src` on the ACK is the SDK's wall clock**, same as every other outbound frame. No latency
   is derived from the `ts_pi`/`ts_src` pair anywhere — that is Phase 28.
</decisions>
