<objective>
Stage 2, part 1. Split the prefs file into a tracked template and a runtime-generated instance,
and make the boot partition the single provisioning surface.

Purpose: `pilot/prefs.json` is tracked in git AND rewritten at runtime — `prefs.py:505-525` saves
the whole file on every `set()` once `_INITIALIZED`, and `pilot.py:595` calls
`prefs.set('SUBJECT', ...)` on every run start. So every experiment dirties a tracked file and
`git pull` on a field unit always conflicts. That is a hard blocker on "clone the repo, run the
installer" as a deployment story.

The core provisioning reframe: **don't reach the Pi — let the Pi read a file a laptop can write.**
Outbound TCP survives VLAN segmentation, client isolation and filtered multicast; a file on the
FAT boot partition depends on no network behaviour at all.

Output: `prefs.template.json` + gitignored `prefs.json`, an every-boot render script, the example
`mics.conf`, and a deliberately-updated integrity manifest.
</objective>
