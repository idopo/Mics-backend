<objective>
Close the orphaned-recording gap Phase 18 could only document — and close it **generically**.

Purpose: Phase 18's backend safety net releases the lease and marks the run errored, but cannot
command the device to stop, because the backend has no channel to one. Phase 26 built that channel
(plan 26-06), so Phase 26 closes the gap. Without this, a crashed pilot leaves the rig recording
until a human notices: filling disk and producing a recording no run claims.

**The trigger is device-neutral by design.** "Run ended uncleanly → tell the device to stop" has
nothing to do with ephys; only the command itself is device-specific. DeepLabCut must be able to
register a stop action without touching one line of the reconciliation logic.
Output: a small registry module, a thin OE adapter, and two call sites in Phase 18's lease router.
</objective>

<task type="auto" tdd="true">
  <name>Task 1: api/device_stop_registry.py — the device-neutral trigger</name>
  <files>api/device_stop_registry.py</files>
  <behavior>
    - A registered stop action is invoked for its class_name with host/port/device context
    - A device class with no registered action is skipped and reported, not treated as an error
    - A stop action that raises yields {"stopped": False, "error": ...} and never propagates
    - Every stopped device's artifact is closed with coverage_complete False
  </behavior>
  <action>
    Create the module. Its docstring must state that it is **device-agnostic**: adding a device here
    means registering a callable from that device's own adapter module, never editing this file.

    - Module-level `_STOP_ACTIONS: dict[str, StopAction]`. `register_stop_action` is idempotent —
      re-registering the same class replaces the entry rather than raising, because the api process
      re-imports adapters on reload.
    - `stop_devices_for_run(db, run_id, reason)`:
      1. `artifacts.open_artifacts_for_run(db, run_id)` — rows with `ended_at IS NULL`. Only devices
         MICS believes are still producing are touched.
      2. For each, read the device's `pilot_hardware_config` row by `(pilot_id of the run,
         device_name)` to get `class_name`, `host`, `port`. **Read the same row the Pi uses** — a
         second source of truth for the OE address is exactly the failure this design forbids.
      3. Dispatch to `_STOP_ACTIONS.get(class_name)`. Unknown class → result
         `{"stopped": False, "skipped": "no stop action registered"}`, which is informational, not
         an error: a device with no remote-stop capability is legitimate.
      4. Wrap each action in `try/except Exception` → `{"stopped": False, "error": str(e)}` and
         `logger.warning`. **Never raise.** Reconciliation runs on a loop; one unreachable box must
         not stop the loop from releasing every other lease.
      5. Always `artifacts.close_artifact(db, run_id, device_name, coverage_complete=False)`,
         whether the stop succeeded or not. The artifact is incomplete either way — the run did not
         end cleanly — and a queryable flag is the entire point of recording coverage.
    - Return one result dict per device, including `device_name`, `class_name`, `host`, `stopped`,
      and `error`/`skipped`, so the caller can log something actionable.
  </action>
