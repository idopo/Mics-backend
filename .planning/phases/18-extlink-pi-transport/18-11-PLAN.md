  <name>Task 2: `_wait_extlink_ready` synthetic pre-state with three exits (EXTLINK-13)</name>
  <files>/home/ido/pi-mirror/autopilot/autopilot/tasks/mics_task.py</files>
  <action>
    At the END of `load_fda_from_json` (after step 5's transition registration), inject the
    synthetic pre-state — but **ONLY when `gate_timeout_s(configs) > 0`**, i.e. at least one
    required external source exists. With zero required sources, nothing is added and a
    non-MICS-Link task's FDA is byte-for-byte what it is today. That zero-overhead guarantee is
    explicit in EXTLINK-13 and is the difference between a substrate and a tax.

    Compose it out of the FDA's ordinary API — `FiniteDeterministicAutomaton` needs no
    special-casing:
    1. `add_method(self._wait_extlink_ready)` and `add_method(self._extlink_timeout)`.
    2. `add_transition(_wait_extlink_ready, <the JSON's declared initial method>, [proceed_pred])`
       where `proceed_pred` returns True when `ready_gate_decision(...)` is `GATE_PROCEED` **or**
       `GATE_SKIP`.
    3. `add_transition(_wait_extlink_ready, _extlink_timeout, [timeout_pred])` where
       `timeout_pred` returns True only for `GATE_TIMEOUT`.
    4. `set_initial_method(self._wait_extlink_ready)` — overriding whatever the JSON declared.

    **Determinism warning:** `add_transition` calls `check_determinism`, which RAISES if two
    transitions out of the same state can both be true simultaneously. Derive both predicates
    from ONE `ready_gate_decision(...)` call result per evaluation and compare against distinct
    outcomes, so they are mutually exclusive by construction. Two independently-computed
    predicates would eventually both read True on a boundary tick and raise at task start.

    `_wait_extlink_ready` itself is a normal blocking state body: it polls each runner's readiness
    on an interval until a transition predicate fires. Readiness is `is_ready()` — lib-defined,
    defaulting to `alive` — NOT merely `alive`. For OpenEphys what must be true before trial 1 is
    *"recording has started"*, not *"a packet arrived"*; a rig that is reachable but failed to
    enter RECORD would pass a liveness gate and then silently record nothing.

    The three exits, in the locked priority order:
    - **all required ready** → the user's declared initial state (normal path).
    - **manual skip** — an `EXTLINK_SKIP_WAIT` flag set by the existing orchestrator-relayed
      message path → the user's initial state, with a warning logged AND a CONTINUOUS event.
      (This event is emitted mid-run, so it does reach ES — unlike anything from `on_run_stop`.)
    - **timeout** at `gate_timeout_s(...)` → `_extlink_timeout`, a terminal state that emits a
      CONTINUOUS event LISTING the sources that never became ready, then aborts cleanly.

    Three escape paths must guarantee the task can never hang: the timeout is finite and always
    fires, manual skip is always available, and the STOP button's existing path is untouched.
    Assert that by inspection and say so in the SUMMARY.

    Keep the added code compact — `mics_task.py` is already 1485 lines. Budget: <= 120 added
    lines across both tasks. If the pre-state's helpers would push past that, put them in a new
    `autopilot/autopilot/tasks/extlink_gate.py` rather than growing `mics_task.py`.
