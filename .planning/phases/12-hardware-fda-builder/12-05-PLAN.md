# Phase 12, Plan 5: Hardware Lib Version Pinning Fixes

**Phase goal:** Fix three version-pinning bugs discovered during phase 12 testing.

**Context:**  
Three related bugs were found after testing the hardware lib versioning system:
1. Task defs are born unpinned, so uploading a new hw lib version silently moves them to the new code — existing task defs should be frozen at the version they were created with.
2. `_validate_task_definition` reads `ast_metadata` from the `hardware_libs` row (always the active version), so a task def pinned to a working older version still shows a "broken" warning.
3. "Restore this version" button in HardwareLibDetail is conceptually wrong — task defs should simply be pinned at creation and never change automatically; rolling back the active version is an unneeded escape hatch.

**Scope:** API + React. No DB schema changes.

## Fix 3: Re-validate when pin is set or deleted

**File:** `api/routers/hardware_libs.py`

Both `set_hw_lib_pin` (PUT, line 710) and `delete_hw_lib_pin` (DELETE, line 774) must re-validate the task def after modifying its pin.

Add this helper near the top of the router (after imports):

```python
def _revalidate_task_def(db, task_def_id: int) -> None:
    """Re-run validation for a task def using its current pins and update status."""
    from routers.toolkits import _validate_task_definition
    row = db.execute(
        sa_text("SELECT fda_json, toolkit_id FROM task_definitions WHERE id = :id"),
        {"id": task_def_id},
    ).fetchone()
    if not row or not row.fda_json:
        return
    fda = row.fda_json if isinstance(row.fda_json, dict) else json.loads(row.fda_json)
    v_status, v_msg = _validate_task_definition(db, fda, row.toolkit_id, task_def_id)
    db.execute(
        sa_text(
            "UPDATE task_definitions SET validation_status = :s, validation_message = :m WHERE id = :id"
        ),
        {"s": v_status, "m": v_msg, "id": task_def_id},
    )
    db.commit()
```

In `set_hw_lib_pin`: call `_revalidate_task_def(db, task_def_id)` after `db.commit()` on line 750.

In `delete_hw_lib_pin`: call `_revalidate_task_def(db, task_def_id)` after the pin is deleted and committed.
