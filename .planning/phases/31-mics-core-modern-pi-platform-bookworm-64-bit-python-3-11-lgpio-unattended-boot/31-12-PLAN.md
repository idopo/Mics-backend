<objective>
Stage 3, part 2. Port the **input** half of `gpio.py`: pin claiming, pull configuration, edge
alerts, callbacks and debounce.

Purpose: this is the half where lgpio is unambiguously better, and it is where the phase's central
24/7 claim is actually earned. Today an edge arrives as a pigpio daemon **tick** — a 32-bit
microsecond counter living in another process's clock domain, mapped into wall time by a
Cristian's-algorithm round-trip estimator that goes stale after any clock step and re-syncs only on
wrap. After this plan, an edge arrives with the kernel's own timestamp, taken in **hardirq
context** (`gpiolib-cdev.c edge_irq_handler()`: *"Just store the timestamp in hardirq context so we
get it as close in time as possible to the actual event"*), on `CLOCK_MONOTONIC`, as 64-bit
nanoseconds.

**Input before output is deliberate.** The loopback harness measures widths through the *input*
path, so the input port has to be right before any output measurement means anything. Getting these
the wrong way round would produce output numbers contaminated by an unported input path.

Output: `gpio.py`'s input classes on lgpio, with the edge timestamp threaded to the boundary where
plan 14 picks it up.
</objective>

<verified_port_facts>
**Migration map (verified against lgpio 0.2.2's shipped Python API):**
| pigpio (in the tree today) | lgpio | Quality |
|---|---|---|
| `pi.set_mode(p, INPUT/OUTPUT)` | `gpio_claim_input` / `gpio_claim_output` | Full |
| `pi.set_pull_up_down(p, PUD_*)` | `lFlags=SET_PULL_UP / SET_PULL_DOWN / SET_PULL_NONE` on the claim | Full |
| `pi.read` / `pi.write` | `gpio_read` / `gpio_write` | Full |
| `pi.callback(p, EITHER_EDGE, f)` | `gpio_claim_alert(h, p, BOTH_EDGES, lFlags)` **then** `callback(h, p, BOTH_EDGES, f)` | Full, and better — the timestamp is kernel-at-interrupt rather than a daemon tick |
| `pi.set_glitch_filter(p, us)` | `gpio_set_debounce_micros(h, p, us)` | Full, with the timestamp-shift caveat |
| `pi.set_pad_strength` / `get_pad_strength` | — | **None.** Delete. |
| `pi.gpio_trigger(p, us, level)` | `tx_wave` two-pulse, or `gpio_write` x2 | Full — but if the call site is an OUTPUT, it belongs to plan 13 |

**Callback signature:** `callback(handle, gpio, edge=RISING_EDGE, func=None)` returns a callback
object with `.cancel()`. The function receives `(chip, gpio, level, timestamp)` where `level` is
0 falling, 1 rising, **2 watchdog timeout** — handle level 2 explicitly rather than treating it as
an edge.

**Two things that are easy to get wrong:**
1. `callback()` does **not** claim the line. `gpio_claim_alert()` must be called first, or the
   callback never fires — silently.
2. `callback()` takes `handle >> 16` internally (`lgpio_extra.py:1127`) because `gpiochip_open`
   packs the chip number into the handle's high bits. Pass the handle from `gpiochip_open`
   unmodified and it works. **Never construct a handle by hand.**

**The notification FIFO (PLAT-10).** `import lgpio` opens `<workdir>/.lgd-nfy<N>` — a RELATIVE
path — and starts a daemon thread **at module import time** (`lgpio_extra.py:273, :331`).
`gpio_claim_alert(..., notify_handle=None)` wires into it automatically. The systemd unit's
`LG_WD` + `RuntimeDirectory` is what makes this work; `31-SPIKE.md` should record that
`.lgd-nfy*` was observed. **Also note `lguGetWorkDir()` calls `chdir()` on the whole process when
`LG_WD` is set** — so do not add any relative-path assumption in this code.

**Debounce timestamp shift (Pitfall 3).** `gpio_set_debounce_micros` deliberately timestamps a
debounced event `debounce` microseconds AFTER the physical edge — stated in the docstring
(`lgpio_extra.py:1000-1001`) and implemented at `lgPthAlerts.c:322`. pigpio's glitch filter did
not. Plan 11 already chose a policy for `i2c.py`'s IRQ lines; **use the same policy here** and
cross-reference it, so the tree does not carry two conventions.

**Do not read a clock inside the callback.** The `ts_ns` argument IS the edge time; anything read
inside the callback includes the full ppoll + FIFO + Python-dispatch latency (lgpio's alert thread
polls with a 0.5 ms `ppoll` timeout, `lgPthAlerts.c:438`). This is the single change that makes the
kernel-timestamp claim visible in the data — the current code discards it
(`Event_Dispatcher.py:77` calls `self.pi.get_current_tick()` in the calling thread). Thread `ts_ns`
outward to the class boundary here; plan 14 connects it to the dispatcher.

**Error containment (Pitfall 8).** Same rule as plan 11: wrap every lgpio call reachable from a
callback in `try/except lgpio.error`, count, never propagate, never set
`lgpio.exceptions = False` globally.

**Chardev line ownership (Pitfall 4).** Lines are released when the process dies, so the pin
reverts to its default state — unlike pigpio, whose daemon outlived the client and kept driving.
For inputs this is harmless. It matters on the reward path and is verified physically in plan 16.
</verified_port_facts>
