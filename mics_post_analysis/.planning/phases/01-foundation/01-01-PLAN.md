# Phase 1, Plan 1: Package scaffold + SESSIONS config + convention resolver

**Phase goal:** A `mics/` package skeleton and a resolver that turns a minimal `SESSIONS` config into fully-resolved session objects by naming convention — including events-only sessions with no ephys.

**Context:**
The toolkit's entry point is a `SESSIONS` list the user edits. Each entry is intentionally minimal; everything else is derived from the SMB share by convention. Ephys + spikes are OPTIONAL — a behavior-only session must resolve without error. This plan is pure Python + unit tests (no notebook, no ES yet).

**Data facts (verified live):**
- Share root: `/mnt/mics-smb/yizharlab/Ido/Mics/sessions/`
- Ephys folder convention: `<subject>s<n>_<YYYY-MM-DD>_<HH-MM-SS>` (e.g. `m74s4_2025-07-09_16-21-05`)
- Open Ephys recording path: `<folder>/Record Node <id>/experiment1/recording1`, raw `<folder>/processed.dat`
- Spike sources (priority order): loose `spikes_<subject>s<n>.pkl` at share root → inline `<folder>/processed.xls`
- ES subject is a descriptive string per protocol (`m74_cue_reward`), NOT the session key — must be explicit in the entry.

## 1. Project scaffold

- `pyproject.toml`: package name `mics`, `src/` layout, deps `pandas`, `numpy`, `elasticsearch`, `matplotlib`; optional extra `ephys` = [`open-ephys-python-tools`] (kept out of base so events-only runs don't need it). Dev deps: `pytest`.
- `src/mics/__init__.py`: export `SessionConfig`, `ResolvedSession`, `load_sessions`.

## 2. `src/mics/config.py` — config dataclasses

```python
DEFAULTS = dict(trigger_channel=17, ttl_channel=16, sampling_rate=30000)
SESSIONS_ROOT = "/mnt/mics-smb/yizharlab/Ido/Mics/sessions"
ES_PRIMARY = "http://132.77.73.217:9200"
ES_SECONDARY = "http://132.77.73.125:9200"
```

- `SessionConfig` (the user-facing entry): `key: str`, `es_subject: str`, `es_session: int | None`, optional `es_host: str = ES_PRIMARY`, `es_index: str = "event_log_v2"`, optional overrides `ephys_folder`, `record_node`, `spike_path`, `trigger_channel`, `ttl_channel`, `sampling_rate`, `run_id: int | None = None`.
- All paths/channels are `None` by default and only override the derived/default values when set.
- `SESSIONS_ROOT`, `ES_*`, `DEFAULTS` are module constants (CONF-04: named + overridable). No hardcoding inside functions.

## 3. `src/mics/resolve.py` — convention resolver

- `ResolvedSession` dataclass: the config fields PLUS derived `ephys_folder: Path | None`, `recording_path: Path | None`, `spike_path: Path | None`, `spike_kind: "pickle"|"xls"|None`, effective channels/sampling, and `has_ephys: bool`, `has_spikes: bool`.
- `resolve_one(cfg, root=SESSIONS_ROOT) -> ResolvedSession`:
  1. Parse `subject` + `n` from `key` via regex `^(?P<subject>.+?)s(?P<n>\d+)$` (so `m74s4` → subject `m74`, n `4`). If the key has no `s<n>` token, ephys is treated as absent unless `ephys_folder` override is given.
  2. Ephys folder: if override given use it; else glob `root/<subject>s<n>_*` and take the single match (warn + pick newest if >1, log if 0 → ephys absent).
  3. Recording path: if folder found, glob `<folder>/Record Node */experiment1/recording1`; set `record_node` from the dir name.
  4. Spike source: if `spike_path` override given use it; else prefer `root/spikes_<subject>s<n>.pkl`, else `<folder>/processed.xls`; set `spike_kind` accordingly; else None.
  5. Effective channels = override ?? DEFAULTS.
  6. `has_ephys = recording_path is not None`; `has_spikes = spike_path is not None`.
- `load_sessions(configs, root=SESSIONS_ROOT) -> list[ResolvedSession]`: map `resolve_one` over the list.
- `ResolvedSession.summary() -> str`: one line — `f"{key}: ES {es_host.split('//')[1]}/{es_index} {es_subject} s{es_session} | ephys {'✓ '+record_node if has_ephys else '—'} | spikes {spike_kind or '—'}"` (CONF-06).

**Filesystem access is read-only.** Use `pathlib.Path.glob`; never write to the share.

## 4. `src/mics/cache.py` — cache scaffold (used by later phases)

- `cache_dir(key) -> Path` under `./cache/<key>/` (gitignored), `mkdir(parents, exist_ok)`.
- `cached_pickle(key, name, build_fn, force=False)`: load `<cache>/<name>.pkl` if present else call `build_fn()`, pickle it, return. Thin helper; later phases use it for events/aligned/spikes.

## 5. Tests — `tests/test_resolve.py`

Run against the live share (these fixtures exist):
1. `resolve_one(SessionConfig(key="m74s4", es_subject="m74_cue_reward", es_session=4))` → `has_ephys` True, `record_node == "Record Node 110"`, `spike_kind == "pickle"`, `spike_path.name == "spikes_m74s4.pkl"`, effective `trigger_channel == 17`.
2. `resolve_one(SessionConfig(key="m74s1", es_subject="m74_cue_reward", es_session=1))` → `has_ephys` True, `spike_kind == "xls"` (inline `processed.xls`, no loose pkl).
3. Events-only: `resolve_one(SessionConfig(key="ghost_s99", es_subject="x", es_session=1))` → no exception, `has_ephys` False, `has_spikes` False, `summary()` shows `ephys —`.
4. Override: `SessionConfig(key="m74s4", ..., trigger_channel=99)` → effective `trigger_channel == 99`.
5. `summary()` returns a non-empty single-line string for each.

(If the live share is unreachable in CI, mark the share-dependent tests with `@pytest.mark.skipif` on `Path(SESSIONS_ROOT).exists()`.)
