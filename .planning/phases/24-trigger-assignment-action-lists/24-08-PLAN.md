<objective>
Give the researcher the two closed sets they are currently typing blind into, stop the backend
accepting a method-less hardware action, and add the one constrained affordance that makes the
detector write impossible to mis-wire.

Purpose:
- **TRIGA-15** — `trigger_name` is free text today. A typo saves cleanly, `self.triggers["TOCH_INT"]`
  is created, and nothing ever fires it: a silent no-op. `init_hardware` calls
  `hw.assign_cb(partial(self.handle_trigger, hardware=hw))` for exactly the hardware whose class
  sets `is_trigger`, and `handle_trigger` maps the firing pin back to that hardware's
  `HARDWARE[group][id]` key — which is what `self.triggers` is keyed by. Report that set
  truthfully and let the researcher pick from it.
- **TRIGA-16** — `fda_validation` checks `CALLABLE_METHODS` only for `type:"method"`, so
  `{"type":"hardware","ref":"MPR121","method":""}` returns **200** and is a silent no-op on the
  Pi: the exact failure class TRIGA-07 exists to prevent. Three of the seven post-execution
  defects in waves 1–2 lived in that seam.
- **TRIGA-17** — the researcher picks the detector device and nothing else; the target key and
  the written value both derive from that call's own return, so reading electrode 2 and writing
  `LICKER0` cannot be expressed. It is a **UI macro** over the general vocabulary: nothing new
  reaches the Pi, and Phase 23's `compute` will work inside a trigger with zero rework.
- **TRIGA-14** — without variables in the operand pickers the canonical payload cannot be
  assembled by clicking at all: its guard is `{"flag":"pin_number"}` and its value is
  `{"flag":"level"}`, both captured variables, while `ConditionBuilder` renders a closed
  `<select>` built from `toolkit.flags` alone.

Output: a backend that derives hardware capability from the lib AST, a hard 422 on a
method-less hardware action, a `trigger_name` dropdown, variables in the operand pickers, and
the constrained detector widget.
</objective>

**1a — `api/hw_introspect.py`** (new, ≤ 150 lines, stdlib `ast` only, no FastAPI/DB imports):

```python
def resolve_class_methods(source_code: str, class_name: str) -> tuple[set[str], bool]:
    """Method names on `class_name` including bases DEFINED IN THE SAME SOURCE.

    Returns (methods, closed). `closed` is True only when every ancestor was resolvable in
    this file — i.e. the method set is exhaustive. Hardware classes inherit from an imported
    `Hardware`, so `closed` is normally False and callers must not reject unknown methods.
    """

def class_capabilities(source_code: str, class_name: str) -> dict:
    """{is_trigger, direction, is_detector, methods, closed} for one class.

    is_trigger : class-level `is_trigger = True` on the class or an in-file ancestor.
    direction  : "input" if a class-level `input = True` is found, "output" for `output = True`,
                 else None. Both flags are truthful class attributes on gpio.Digital_In /
                 Digital_Out — do NOT infer direction from the class name.
    is_detector: `detect_change` is in the resolved method set. Capability, not class identity,
                 mirroring the Pi's _has_detector_capability (24-06 / TRIGA-12).
    """

def toolkit_hw_capabilities(db, hardware_module_ids: list[int]) -> dict:
    """{"trigger_sources": [...], "detector_refs": [...], "module_methods": {name: [str]}}

    One SQL join over hardware_modules -> hardware_libs -> hardware_lib_versions
    (active_version_id.source_code), parsing each distinct version once per call.
    trigger_sources entries: {"hw_id": module.name, "module_id": id, "class_name": ...,
                              "direction": "input"|"output"|None}, sorted inputs first then
                              outputs, each group alphabetical.
    A module whose lib has no active version, or whose class is missing from the source, is
    skipped silently — never a 500 on a toolkit read.
    """
```
Implementation notes:
- Walk only top-level `ast.ClassDef` nodes; index them by name; resolve bases by `ast.Name.id`
  (ignore `ast.Attribute` bases like `gpio.Digital_Out` unless the bare tail matches an in-file
  class). Track a `seen` set so a cycle terminates.
- Class attributes: `ast.Assign` / `ast.AnnAssign` in the class body whose value is
  `ast.Constant(True)`.
- MRO order does not matter here — every question is "does any ancestor set this".
- Memoise per `(version_id)` with `functools.lru_cache` on a small parse helper keyed by the
  source hash, so `GET /toolkits` does not re-parse the same lib per toolkit.
