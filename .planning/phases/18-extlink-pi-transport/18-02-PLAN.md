       an egress ITEM is a ZERO-ARG CALLABLE. The worker only ever does `send_fn(item)`;
       `ExternalHardware` constructs its worker as `EgressWorker(send_fn=lambda fn: fn(), ...)`
       so the item invokes itself on the worker thread.

       Why the callable model and not a data-item model: a `role: "none"` device has no socket
       and therefore no transport-specific `send_fn` the base class could possibly supply, so
       the base class cannot own the "how to send" half. Each call site closes over its own
