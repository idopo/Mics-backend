       Recording the placement immediately is what makes a newly added state survive a refresh
       without needing a drag first.

    2. Toolkit-sync effect — compute the missing set and its placements OUTSIDE the `setNodes`
       updater, then append:
       ```ts
       useEffect(() => {
         if (!fdaJson || !canvasInited) return
         setNodes(prev => prev.map(n => ({
           ...n,
           data: { ...n.data, state: fdaJson.states[n.id] ?? n.data.state, toolkit, warning: stateWarnings[n.id] },
         })))
         if (!toolkit?.states) return
         const known = layout.current()
         const missing = toolkit.states.filter(s => !(s in known))
         if (missing.length === 0) return
         const taken: Record<string, XY> = { ...known }
         const placements = missing.map(s => {
           const position = placeNewState(taken)
           taken[s] = position
           return { id: s, position }
         })
         setFdaJson(f => f ? { ...f, states: { ...f.states, ...Object.fromEntries(missing.map(s => [s, {}])) } } : f)
         setNodes(prev => [...prev, ...placements.map(({ id, position }) => ({
           id, type: 'stateNode', position,
           data: { name: id, state: {}, isInitial: false, toolkit },
         }))])
         layout.record(placements)
       }, [fdaJson?.states, toolkit, stateWarnings])
       ```
       Deriving `missing` from `layout.current()` instead of `prev` is equivalent (the layout map
       is seeded with exactly one entry per node at canvas init and gains one per creation) and it
       is what lets the placement run outside the updater. Preserve the existing
       `// eslint-disable-next-line` comments and the `as any` casts on the appended node data if
       `tsc` still needs them — those were there because `FdaState` is `{}` for a fresh state.

    3. `deleteState` — deliberately do NOT prune the layout map. A deleted state's slot stays
       reserved for the session, and `resolvePositions` (plan 29-03) drops entries for states that
       no longer exist the next time the definition loads, so the stale key self-heals. Add a
       one-line comment saying so, so a later reader does not read it as a leak.

    4. Change nothing about edges, the autosave, or the hydration path.
