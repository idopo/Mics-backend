<objective>
Build `dlc-link-convert`: a DeepLabCut `.h5` export becomes a wide replay file the SDK's existing
replay driver plays back at real time. This is the no-GPU regression test DLC-09 requires and the
thing that makes the whole integration testable by anyone without a camera, a GPU or a trained model.

Purpose: DLC-09. Per D-29 this is deliberately SECOND - the live-shaped video-to-Processor path is
built and proven first, and this is the regression vehicle that follows it.

Output: a converter whose read half goes through `pandas.read_hdf` on the PyTables backend, whose
write half satisfies `sdk/src/mics_link/replay_io.py`'s wide contract exactly, and whose pure core
is unit-tested on a machine with no pandas at all.
</objective>

`ConvertError(Exception)`, always naming the input path or the offending column.

`flatten_columns(columns, signal_map)`: takes the DataFrame's column labels as a list of tuples - a
DeepLabCut `.h5` export carries a three-level MultiIndex of `(scorer, bodypart, coord)`, and for a
multi-animal export a four-level `(scorer, individual, bodypart, coord)` - and returns an ordered
mapping from column POSITION to emitted signal name, using only names present in `signal_map`.
Rules:
- The scorer level is ignored; there is exactly one scorer in an export and its name is an
  implementation detail of the training run.
- `coord` values `x`, `y` and `likelihood` map to that bodypart's corresponding emitted signal name
  taken from `signal_map.SIGNALS`. A `coord` outside those three is skipped and counted.
- A bodypart present in the file but absent from the map is skipped and counted - the researcher
  declared a subset on purpose (coordinates are opt-in per keypoint per DLC-03).
- A bodypart present in the map but absent from the file raises `ConvertError` naming it: that is a
  map/model mismatch and silently emitting an all-empty column would produce a replay that proves
  nothing.
- For a four-level multi-animal export, the individual level needs handling that the three-level case
  does not. DeepLabCut writes UNIQUE bodyparts under the individual literally named `single`, while
  per-animal parts appear under each real individual (`1`..`5` in the target project). So: accept the
  export when the only individuals present are `single` and at most one real individual, and raise
  `ConvertError` naming `single_animal=True` and listing the individuals found when more than one
  real individual is present - the same refusal, for the same reason, as the Processor's rank guard
  (D-07/D-08), sharpened by D-37: with `identity: false` the individual index is assigned post-hoc by
  `stitch_tracklets`, which DLC-Live never runs, so a per-individual column is not a stable identity
  even inside one file. Columns under `single` map by bodypart name exactly as the three-level case
  does, which is what makes the `LED_on`/`LED_off` demo (D-38) convertible with no special casing.
- Assert no produced column name is literally `signal`: `replay_io._detect_shape` treats a header
  containing `signal` without `value` as AMBIGUOUS and raises at read time, which would turn a
  correct conversion into an unreadable file. The name gate in `dlc_link.names` already makes this
  impossible, so this is a belt-and-braces assertion with a comment saying which upstream check it
  duplicates and why the duplication is deliberate.

`rows_to_wide(rows, position_to_name, fps, likelihood_threshold=None, start_t=0.0)`: takes an
iterable of positional row tuples plus the mapping, and yields `(t, {signal_name: value})` dicts.
`t` is `start_t + index / fps` - the DLC export has no time column, so time is reconstructed from
the frame index and the video's fps, and the docstring must say so plainly. When
`likelihood_threshold` is given, a bodypart whose likelihood for that row is below it emits EMPTY
cells for that bodypart's x and y - not a zero, not a hold - which is exactly the "no sample"
semantic `replay_io` documents and is how an occlusion survives the round trip. The likelihood
column itself is always emitted with its real value; suppressing it would delete the very signal
that tells the FDA the keypoint is untrusted.

`write_wide_csv(path, header_names, rows, newline_utf8=True)`: writes the header `t` followed by the
signal names in a stable sorted order, then one row per sample, opening with `encoding="utf-8"` and
`newline=""` exactly as `replay_io` reads them (Windows correctness, SDK-14c/e - the vision box is a
Windows machine). An absent value writes an EMPTY cell, never the string `None`, never `nan` and
never `0`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| researcher `.h5` export -> converter -> replay file -> Pi | An untrusted binary file from the researcher's machine becomes scalars that drive an FDA on a device that actuates hardware. |
| replay file -> `mics_link.replay` -> Pi ROUTER | The same rate and IOLoop concerns as the live path, at whatever rate the replay is played. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-35-20 | Tampering | column-name divergence between the export and the deployed lib | mitigate | Column names come only from the loaded signal map; a map bodypart missing from the file raises `ConvertError` naming it rather than emitting an all-empty column that would produce a replay proving nothing. |
| T-35-21 | Tampering | occlusion silently becoming a real value | mitigate | A below-threshold sample writes a zero-length cell, never `0`, `nan` or `None`; the round-trip test asserts those timestamps yield no x/y tuples at all. |
| T-35-57 | Tampering | writing the converted CSV, or a temporary file, into the user's read-only DLC project | mitigate | `--out` is required with no default and is refused when it resolves inside the `.h5`'s directory or a DLC project root, with `D-44` named; the atomic write's temporary file lives beside `--out`, never in cwd or the system temp root. A test runs the converter with an empty directory as cwd and asserts it stays empty. |
| T-35-22 | Denial of Service | an enormous export exhausting memory | accept | `pandas.read_hdf` loads the whole frame; a 20-minute 30 fps 8-bodypart export is roughly 36k rows, comfortably in memory on the target box (12 GB free VRAM, ordinary RAM unconstrained). `--max-rows` exists for the pathological case. Recorded rather than engineered around. |
| T-35-23 | Denial of Service | replaying faster than the Pi's shared IOLoop can absorb | mitigate | The replay driver's `--mode realtime` is the documented default in the runbook; `--mode fast` is called out as a local-testing-only mode that must never be pointed at a live pilot. |
| T-35-24 | Elevation of Privilege | a hostile `.h5` reaching a deserialiser | accept | `pandas.read_hdf` on the PyTables backend is not a pickle path for a DataFrame written by DeepLabCut, and the file originates on the researcher's own machine. Named so the choice is deliberate; adding `h5py` to "harden" this would violate D-09c and is not proposed. |
| T-35-SC | Tampering | package-manager installs | mitigate | This plan installs nothing. `pandas` and `tables` are declared as the optional `convert` extra and are already present on the target vision box at 2.3.3 and 3.11.1 (verified 2026-08-31). `h5py` is forbidden. |
