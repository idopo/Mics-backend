<objective>
Make node positions load from and save to `task_definitions.ui_layout`, on a persistence path
completely separate from the FDA autosave.

Purpose: `fdaToNodes` (`TaskEditor.tsx:144`) recomputes `position` from the array index
(`x:(i%4)*270, y:floor(i/4)*170`) on every mount, so every drag dies on reload. And the FDA
autosave (`TaskEditor.tsx:318-351`) deliberately holds its PUT behind two guards; if layout rode
that path, dragging a node while a trigger was half-built would silently refuse to save the
position and would flash "Unsaved…" for a change with no semantic content (CANVAS-10).

Output: `useLayoutPersistence.ts` and a small `TaskEditor.tsx` diff covering hydration and drag.
New-state placement and the restore action are plan 29-07.
</objective>

The backend has a layout-only fast path: a PUT whose body carries `ui_layout` and NOTHING else
skips FDA validation entirely. `JSON.stringify` drops `undefined` keys, so
`updateTaskDefinition(id, { ui_layout })` hits that path. **Never add `display_name` or
`fda_json` to a layout PUT** — doing so silently re-enables validation and can 4xx a drag.

`fdaToNodes` (line ~144 pre-29-01; re-locate by name):
```ts
function fdaToNodes(fdaJson: FdaJson, toolkit: ToolkitRead | null, stateWarnings: Record<string, string>): Node[] {
  return Object.entries(fdaJson.states ?? {}).map(([name, state], i) => ({
    id: name,
    type: 'stateNode',
    position: { x: (i % 4) * 270, y: Math.floor(i / 4) * 170 },   // <-- the layout-reset bug
    data: { name, state, isInitial: name === fdaJson.initial_state, toolkit, warning: stateWarnings[name] },
  }))
}
```

The canvas-init effect (line ~247 pre-29-01) — fires ONCE per mount:

useEffect(() => {

<!-- ⚠ THE SEEDING DISCIPLINE. Do not weaken it. -->
`seededIdRef` (line ~234) exists because React Query refetches on window focus and after every
save, and re-seeding on each refetch was overwriting work in progress — a half-built trigger
assignment (which correctly does not autosave) vanished on the next refocus.

Layout hydration must obey the same rule: read `taskDef.ui_layout` ONCE, at canvas init, and never
again. After that the hook's in-memory map is authoritative. Concretely:
- the layout mutation must NOT call `qc.invalidateQueries({ queryKey: ['task-definition', numId] })`
  — that would refetch on every drag and churn the whole editor
- no effect may depend on `taskDef.ui_layout` after `canvasInited` is true

<!-- ⚠ THE AUTOSAVE THIS MUST NOT TOUCH (line ~318-351) -->
```ts
useEffect(() => {
  if (!fdaJson || !canvasInited) return
  ...
  const incomplete = (fdaJson.trigger_assignments ?? []).filter(a => !isCompleteTrigger(a))
  if (incomplete.length) { setSavedMsg(`Not saved — finish or remove trigger '...'`); return }
  const halfBuilt = ...find(({ action }) => !isCompleteAction(action))
  if (halfBuilt) { setSavedMsg(`Not saved — finish action[...] in state '...'`); return }
  setSavedMsg('Unsaved…')
  autoSaveTimerRef.current = setTimeout(() => saveMutation.mutate(), 1500)
}, [fdaJson])
```
It is keyed on `fdaJson`. A drag must therefore never call `setFdaJson` — not even with an
identical object — or every drag re-arms this timer and re-runs the FDA PUT. That is the whole of
CANVAS-10 in one sentence.

<!-- react-flow drag callback, @xyflow/react ^12 -->
```ts
type OnNodeDrag<NodeType extends Node = Node> = (event: ReactMouseEvent, node: NodeType, nodes: NodeType[]) => void
// <ReactFlow onNodeDragStop={...}> — `nodes` is the set that was dragged (multi-select), `node` the primary
```
Use `onNodeDragStop`, not an effect on the `nodes` array: the array changes on every mouse-move
during a drag, and an effect would fire a PUT per frame.

  <action>
    Create the hook. Pin this surface — plan 29-07 is written against it:

    ```ts
    export interface LayoutPersistence {
      /** Current known positions. Ref-backed: reading it never re-renders. */
      current: () => Record<string, XY>
      /** Record the hydrated positions at canvas init. Does NOT write to the server. */
      seed: (positions: Record<string, XY>) => void
      /** Merge dragged/placed positions and schedule a debounced PUT. */
      record: (entries: ReadonlyArray<{ id: string; position: XY }>) => void
      /** Replace the whole map and PUT immediately (used by 'Restore default layout'). */
      replaceAll: (next: Record<string, XY>) => void
      /** Status string for the header. Empty when idle. */
      layoutMsg: string
    }

    export function useLayoutPersistence(taskDefId: number): LayoutPersistence
    ```

    Implementation:
    - `positionsRef = useRef<Record<string, XY>>({})` — the authoritative map. A ref, not state:
      a drag must not re-render the editor.
    - `const [layoutMsg, setLayoutMsg] = useState('')`
    - `const mutation = useMutation({ mutationFn: (nodes: Record<string, XY>) => updateTaskDefinition(taskDefId, { ui_layout: { nodes } }), onSuccess: ..., onError: ... })`
      **No `invalidateQueries` in `onSuccess`.** Set `setLayoutMsg('Layout saved ✓')` and clear it
      after 1500 ms; on error `setLayoutMsg('Layout not saved: ' + e.message)` and leave it up.
    - `seed(positions)`: assign `positionsRef.current = { ...positions }`. No PUT. Rationale to put
      in a comment: the computed layered layout is deterministic from the FDA, so re-deriving it on
      the next open gives the same arrangement — writing it on every page view would be a PUT per
      view for no gain. The first write happens on the first drag or the first restore.
    - `record(entries)`: merge into `positionsRef.current`, `setLayoutMsg('Layout…')`, and
      (re)start a `setTimeout` of **600 ms** that fires `mutation.mutate(positionsRef.current)`.
      Clear any pending timer first. Clear the timer in the hook's unmount cleanup.
    - `replaceAll(next)`: assign, clear any pending debounce timer, and `mutation.mutate(next)`
      immediately.
    - `current()`: `() => positionsRef.current`.

    Constraints, all load-bearing:
    - This file must contain NO reference to `fdaJson`, `setFdaJson`, `fda_json`, `savedMsg`, or
      `saveMutation`. It is the separate path; keeping it textually separate is what makes that
      checkable.
    - Explicit return types on the export. No `any`.
    - Under 110 lines.

    It is a React hook, so it gets no `.mts` unit test. Its separation is proven structurally by
    Task 3's greps and behaviourally at the 29-08 checkpoint.
