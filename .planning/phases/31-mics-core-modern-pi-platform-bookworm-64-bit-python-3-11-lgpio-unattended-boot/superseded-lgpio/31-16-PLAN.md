<the_gates>
**G1 (primary, comparative).** For every profile x load, the lgpio arm's `err_p99` and `err_sd`
must be **<= 1.25x** the pigpio baseline captured on the same hardware. `n_missing` must be **0** in
every capture. This gate needs no arbitrary numbers and is the one that carries the weight.

**Absolute (secondary).** They exist so a *jointly bad* baseline cannot pass by comparison alone:
`valve` `err_p99` <= 1.0 ms; `valve_short` `err_p99` <= 0.5 ms; `ttl` `err_p99` <= 200 us;
`train` `period_sd` <= 200 us; `train` |`rate_ppm`| <= 100.
`31-RESEARCH.md` rates these MEDIUM confidence — proposed from the science, not measured. If an
absolute threshold fails while G1 passes, that is a conversation with the user about the threshold,
**not** a silent pass and **not** an automatic phase failure. Present both verdicts separately.

**The four bounded 24/7 experiments** (they replace the calendar):

**V1 — forced clock step. The core claim.** While a capture runs:
```bash
sudo timedatectl set-ntp false
sudo date -s '+1 hour'        # and, in a second run: sudo date -s '-1 hour'
sudo timedatectl set-ntp true
```
Machine-checkable assertions: `t_mono_ns` strictly increasing with **no discontinuity** (the
interval between the pulses straddling the step equals the commanded interval within the profile's
jitter budget); derived `t_utc` steps by **exactly** the applied amount and by nothing else (this is
CORRECT behaviour, and saying so is what keeps the claim honest); the pilot does not crash, the
session continues, and `_dropped_no_clock` / `_dropped_on_send` stay 0.
**Run the identical experiment on the pigpio baseline and record the contrast** — there,
`ticks_to_timestamp()` stays corrupted from the step until the next 32-bit wrap, because
`synchronize()` only re-runs when `ticks < _last_synced_tick`. The contrast is the evidence; the
lgpio result alone is only half an argument.

**V2 — counter wraparound.** Already captured in plan 08 (75-minute pigpio run). For lgpio no
experiment is needed — 64-bit nanoseconds wraps in ~584 years — but the harness asserts the field
width and monotonicity so the claim is machine-checked rather than asserted in prose.

**V3 — overnight soak, 8-12 h, unattended, once.** `train` profile plus periodic `valve` pulses,
running under the **real systemd unit**. Assertions: `n_missing == 0`; `err_p99` in the last hour
within 1.25x of the first hour (no thermal or drift degradation); pilot RSS flat within 5 %;
journal size within its configured cap; `systemctl show mics-pilot -p NRestarts` returns 0.
This is the one experiment that genuinely needs wall-clock time, and it runs while nobody is
watching — which is the point.

**V4 — restart and reboot resilience.**
- `sudo systemctl kill -s SIGKILL mics-pilot` -> the unit restarts within `RestartSec`, the pilot
  re-handshakes with the backend, and `/run/mics/.lgd-nfy*` is recreated.
- Repeat the kill **10x in 30 s** to prove `StartLimitIntervalSec=0` prevents the `failed` latch.
- `sudo reboot` -> the pilot is up and connected with **no human action**. That sentence is the
  phase goal; this is where it is proven.
- **Physically verify the fail-safe output level after SIGKILL with a solenoid energised**, with a
  meter. Chardev lines are released when the process dies, so the pin reverts to its default state —
  unlike pigpio, whose daemon kept driving it. That is probably an improvement, but it is a
  **behaviour change on the reward path** and must be verified per device, not assumed.
</the_gates>
