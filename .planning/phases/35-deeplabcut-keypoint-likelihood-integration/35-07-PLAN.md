reach pilot 3 through the Phase 34 SDK, and a transition **authored in the browser** on
`dlc_cam1.nose_likelihood` ANDed with `dlc_cam1.nose_x` fires and shows up in Elasticsearch.

Purpose: DLC-07, DLC-08 and the first half of DLC-10, plus roadmap success criteria 1 and 2.
**This is the first time the FDA editor's extlink operand picker is exercised by a human at all.**
Phase 18 recorded EXTLINK-19 with a split verdict because task def 434's transitions were authored via
the API and plan 18-14's UI "was not clicked"; Phase 34 reused those existing transitions and did not
touch the picker either. Budget for it not working.

**HARD CONSTRAINT.** The agent does NOT run git on the Pi, does NOT start or stop the pilot process,
and does NOT run Python on the Pi. Every rig and vision-box action below is USER-RUN: the agent
supplies the exact command, the user runs it and reports back. There is no autonomous rig task in this
plan and there must never be one.
</objective>

<what_is_expected_to_go_wrong>
Named in advance so a failure is diagnosed rather than improvised. Report which of these it was:

1. **The export.** A DLC 3.0 `export_model` emits a single `.pt` while DLC-Live can still complain
   about a missing pose_cfg (DeepLabCut-live issue 137, image.sc). D-09 calls this the likely first
   real obstacle. It is an upstream packaging problem, not a MICS one.
2. **The picker.** `buildViewOptions` has never been observed enumerating dotted extlink keys against
   a live toolkit in a browser. Plan 35-06 proved the API payload carries the signals and that the
   served bundle is current, so if the picker is empty the fault is in the frontend and not in the
   data - say which.
3. **Start order.** Pilot 3's DLC config row is `required: false`, so there is no readiness gate
   holding the run for the sender: the correct order is RUN FIRST, then sender. Starting the sender
   first produces a flushed DEALER backlog delivered in a burst on connect, which looks like a
   working run but is not live streaming - exactly Phase 34 run 582's caveat 1.
4. **`single_animal=True`.** The Gili project is multi-animal. Without the flag the pose array is
   three-dimensional and `DLCProcessor` refuses loudly by design. That refusal is a correct result,
   not a bug.
</what_is_expected_to_go_wrong>
