<objective>
Stage 3, part 4. Delete the daemon.

Purpose: every pigpio-era workaround in this codebase exists because pigpio is a **separate
process** — the tick synchroniser, the script store/run/status/delete dance, the
`PI_SCRIPT_INITING` polling loop, the daemon-lifecycle code in `pilot.py`. Plans 11-14 removed the
first three. This plan removes the last one, and with it the reason all of them existed. The port
should be a net **reduction** in code; if it is not, something was ported that should have been
deleted.

**The `--final` guard inversion is the trap in this plan.** `tools/tree_integrity/final_checks.py`
`f3_toggles` currently asserts that `self.enable_ntp_and_wait()` and `self.disable_ntp()` are
present **in commented form**, along with the two anchor comments `# ---- CLOCK SETUP ----` and
`# Freeze wall clock so it never jumps during the task`. (The guard is a whole-file substring
search — it does not carry a line number, which is why it kept working after Phase 30 shifted the
block.) That
assertion was **deliberately inverted** during Phase 30 when the user deferred the NTP restoration,
precisely so a comment sweep could not eat the block. Deleting the block without retiring the guard
makes `--final` fail loudly — which is the guard working, not a bug. Retire it deliberately, in the
same commit, with the reason recorded.

And the reason is good: the clock-freeze block exists **because** a wall-clock jump corrupted the
estimated tick->timestamp mapping. Plan 14 replaced that estimate with kernel timestamps, so
freezing the wall clock is no longer necessary. This is not a deferral being quietly dropped; it is
a deferral being **resolved by making it unnecessary**, and the summary must say so in those terms.

Output: a pigpio-free tree, a clean shutdown path, and two static gates.
</objective>
