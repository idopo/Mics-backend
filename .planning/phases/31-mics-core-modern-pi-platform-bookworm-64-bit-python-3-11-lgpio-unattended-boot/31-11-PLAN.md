<objective>
Stage 3, part 1. The lowest-risk half of the port: chip resolution and I²C.

Purpose: these two are where lgpio maps most cleanly and where a mistake is cheap to find. Doing
them first gives the rest of Stage 3 a working handle to build on, and it front-loads the one piece
of forward-compatibility work the phase promises — resolving the gpiochip **by label** so the rig is
Pi 5-capable.

Why by label matters, with evidence: on Pi 5 under Bookworm the header chip has moved index
**three times** — `gpiochip4` originally, `gpiochip0` on kernel 6.6.45, `gpiochip15` on kernel
6.12.96+rpt-rpi-2712. The `/lib/udev/rules.d/60-gpiochip4.rules` symlink Raspberry Pi shipped as a
fix for the first move is itself now defunct after the second. There is no stable index. A
hardcoded `gpiochip_open(0)` is not merely fragile; it has already broken twice on the target OS.

Output: `lgchip.py`, a ported `i2c.py`, and two test modules driven by the plan-01 fake.
</objective>

<verified_port_facts>
**Chip resolution (PLAT-12).** Verified lgpio 0.2.2 signatures:
- `gpiochip_open(n)` -> handle, with `n` encoded in the handle's **high 16 bits**
  (`lgpio_extra.py:411-414`). Never construct a handle by hand.
- `gpio_get_chip_info(h)` -> `[status, lines, name, label]` (`lgpio_extra.py:432-443`).
- Both raise `lgpio.error` on failure, because the module global `exceptions` is True
  (`lgpio_extra.py:219-228`).

Label allowlist, ordered: `pinctrl-rp1` (Pi 5, 54 lines), `pinctrl-bcm2711` (Pi 4, 58 lines),
`pinctrl-bcm2835` (Pi 2/3/Zero), plus a `pinctrl-*` prefix fallback.
**Note the correction:** CONTEXT §5 named `pinctrl-bcm2835` as the Pi 4 label; it is not — that is
Pi 2/3/Zero. The design is unaffected, only the ordering. Confirm against `31-SPIKE.md`.

The reference implementation is in `31-RESEARCH.md` `## Architecture Patterns -> Pattern 1`. Use it
as a starting point, not as gospel — in particular its `lines >= 54` guard would reject a Pi 2/3
board, so decide the threshold against the line counts `31-SPIKE.md` actually recorded and say what
you chose.

`prefs` gains an optional `GPIOCHIP_LABEL` so a future board is pinned without a code change. Add
it to `pilot/prefs.template.json` as `null`/absent-by-default with a comment in the summary.

**I²C (PLAT-13).** The whole surface is in `autopilot/autopilot/hardware/i2c.py` — verified: zero
`i2c_*` pigpio calls anywhere else in the tree. Counts: 2x `i2c_open`, 14x `i2c_write_byte_data`,
7x `i2c_read_i2c_block_data`, 6x `i2c_read_byte_data`. `i2c.py` carries **44** pigpio references
in total, so there is non-`i2c_*` pigpio surface in it too (mode/pull/callback on IRQ lines) —
enumerate with `grep -n pigpio autopilot/autopilot/hardware/i2c.py` and handle every one.

Mapping (verified against the shipped Python API):
| pigpio | lgpio | Quality |
|---|---|---|
| `i2c_open(bus, addr, flags)` | `lgpio.i2c_open(bus, addr, flags=0)` | Full, identical signature |
| `i2c_write_byte_data(h, reg, v)` | `lgpio.i2c_write_byte_data(h, reg, v)` | Full, identical |
| `i2c_read_byte_data(h, reg)` | `lgpio.i2c_read_byte_data(h, reg)` | Full, identical |
| `i2c_read_i2c_block_data(h, reg, n)` | `lgpio.i2c_read_i2c_block_data(h, reg, count)` -> `(count, bytearray)` | Full, **different return shape** — verify each of the 7 call sites |
| `pi.stop()` | `gpiochip_close(h)` / `i2c_close(h)` | Full |

**Pitfall 8 — lgpio raises where pigpio returned negative numbers.** `_u2i()` raises `lgpio.error`
on any negative status. A `TX_QUEUE_FULL` (-96) or `GPIO_BUSY` (-79) thrown out of a hardware
callback unwinds the caller **before its remaining writes run** — including the view update an FDA
transition depends on. That hazard is already documented in the tree at
`Event_Dispatcher.py:70-75`. Wrap every lgpio call reachable from a hardware/tracker callback in
`try/except lgpio.error`, count the failures following the existing `_dropped_on_send` pattern, and
never let one propagate. **Do NOT set `lgpio.exceptions = False` globally** — silent negative
returns are worse than counted exceptions.

**Pitfall 10 — a stray `pigpiod` makes lgpio's claims fail** with `LG_GPIO_BUSY`. The installer
purges it (plan 07). Surface the error message clearly rather than retrying: a busy-line error is a
loud, immediate signal that something else owns the pin, which pigpio never gave you.
</verified_port_facts>
