<objective>
Build the pilot-scoped fault transport: a ZMQ key the Pi can use when no run exists, an
orchestrator handler, a health container in `OrchestratorState` mirrored to Redis, and
`device_health` on `/pilots/live`.

Purpose: FAULT-06 — `Event_Dispatcher` is run-scoped by construction (it is built with `subject`,
`session` and `run_id`), so the faults that happen before any run exists physically cannot use it.
FAULT-08 — Phase 19 is superseded; this builds the health path it would have built, but carrying
pilot-scoped faults rather than the narrower `.alive` liveness case, so re-scoping Phase 19's case
onto it later stays cheap. FAULT-07 — the lifetime rule is the design point: a run-scoped liveness
warning clears when the run ends, but a pilot with no GPIO daemon is still broken after the run
ends, so a pilot-scoped fault persists and clears only when the same operation next succeeds.

Output: the transport, end to end from ZMQ key to `/pilots/live`. The Pi emitters are plans 08 and
09; the React surface is plan 07.

This plan is Wave 1 and touches only backend code — nothing here reaches a Pi.
</objective>

**`/pilots/live` reads Redis, not `OrchestratorState`.** `orchestrator/orchestrator/api.py:24-59`
iterates `station.redis.scan_iter("pilot:*")` and builds its response from the hash fields
`updated_at`, `state` and `active_run` (the last `json.loads`-ed). The in-memory
`state.snapshot()` version of the endpoint is commented out above it. **A health field that is
only written to `OrchestratorState` will not appear in the API.** It must be mirrored into the
same `pilot:<key>` hash, the way `_redis_set_active_run` already mirrors `active_run`.

**`OrchestratorState`** (`orchestrator/orchestrator/state.py`) — `RLock`-guarded, with
`_pilots: Dict[str, Dict[str, Any]]` and `_last_seen`. Existing accessors: `update_handshake`
(which deliberately preserves `active_run` across a handshake), `update_ping`, `set_state`,
`get_pilot`, `is_connected`, `snapshot`, `set_active_run`, `get_active_run`, `resolve_pilot_key`.
Follow that shape: every new accessor takes the lock and returns a copy.

**ZMQ key wiring** is a dict literal at `orchestrator/orchestrator/main.py:71-80`
(`gateway.listens.update({...})`). The precedent for a pilot-level, non-run message is
`"HARDWARE_LIB_TEST_RESULT": station.handle_hardware_lib_test_result`, sent from the Pi at
`pilot.py:650` as `self.node.send(self.parentid, "HARDWARE_LIB_TEST_RESULT", {...})` with
`parentid == 'T'`.

**Handler signature:** `def on_x(self, msg: Message)` where `msg.value` is the payload dict and
`msg.sender` is the pilot key. `Message` is on the ZMQ hot path and is **excluded from this
work** — do not modify it, do not add fields to it.

**`_redis_touch(pilot_key)`** writes `updated_at`; call it from any new handler so a fault report
also counts as liveness.

**Test harness:** `orchestrator/tests/test_on_state.py` builds a station with
`object.__new__(OrchestratorStation)` and assigns `MagicMock()` members, avoiding `__init__`
entirely. Copy that idiom. The tests currently **cannot run anywhere** — the dev host has no

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Pi (ZMQ DEALER) -> orchestrator ROUTER | Untrusted-by-construction payload from a device on the lab network crosses into orchestrator state |
| orchestrator -> Redis -> API -> browser | A pilot-authored string is stored and later rendered |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-32-19 | Denial of service | `on_pilot_fault` with a malformed or flooding payload | mitigate | Missing `fault_key` is dropped and logged (Test 3); a repeat raise of the same key increments `count` rather than appending, so a looping Pi cannot grow the health dict without bound |
| T-32-20 | Tampering | A pilot raising a fault key that stops a run | mitigate | Test 5 asserts the handler never calls `stop_run`, `mark_run_error`, `gateway.send` or `set_active_run`; HEALTH-06 is carried forward as an enforced property, not a convention |
| T-32-21 | Spoofing | `msg.sender` as the pilot identity | accept | ZMQ DEALER identity on a lab-local network is the existing trust model for every handler including `on_task_error`; this plan does not weaken it and does not introduce a new authentication surface |
| T-32-22 | Information disclosure | Pi-authored `message`/`detail` rendered in the browser | mitigate | Plan 07 renders through React's default text escaping and must not use `dangerouslySetInnerHTML`; recorded here so plan 07's executor inherits the constraint |

No package-manager installs beyond adding `pytest` to `orchestrator/requirements.txt` — a PyPI
package already present in `api/requirements.txt` and in this project's toolchain, so no new
supply-chain surface is introduced.
</threat_model>
