  <files>api/preflight_external_devices.py</files>
  <behavior>
    - An unreachable device yields external_device_unreachable carrying device_name and host
    - A device reporting itself busy yields the distinct external_device_busy kind
    - A resolved target already recorded by another run yields artifact_path_collision
    - No probe exception ever escapes; a probe failure becomes an issue, never a raise
    - A pilot with no external / artifact-producing device yields no issues at all
  </behavior>
  <action>
    Create the module. Docstring: the **kinds** are device-neutral and carry a device name; only the
    per-device probe in `DEVICE_PROBES` may know a specific device. Adding DeepLabCut means adding
    one entry to that dict, never a new kind.

    `external_device_issues(db, pilot_id, run_id=None)`:
    1. Read this pilot's `pilot_hardware_config` rows. Select the ones that either declare
       `produces_artifacts: true` or have a `class_name` present in `DEVICE_PROBES`. Everything else
       is untouched — `test_non_artifact_module_unaffected` asserts exactly this.
    2. **Reachability / busy:** for a device with a registered probe, call it with
       `(host, port, config)`. The probe returns `None`, or an issue dict of kind
       `external_device_unreachable` or `external_device_busy`. Wrap each probe in
       `try/except Exception` → an `external_device_unreachable` issue whose detail carries the
       exception text. `preflight_validate`'s existing steps already use this non-blocking
       `try/except` posture; follow it. **A probe must never produce a 500** — the researcher needs
       a blocked run with a reason, not a broken page.
    3. **Artifact path collision:** for a device declaring `produces_artifacts`, resolve its target
       with `artifact_paths.resolve_artifact_target(db, run_id, template, device_name)` (template =
       `config.get("artifact_path_template", DEFAULT_ARTIFACT_TEMPLATE)`) and call
       `artifacts.find_path_collision(db, target_path, run_id=run_id)`. A hit becomes an
       `artifact_path_collision` issue naming the path and the run that already recorded there.
       When `run_id` is None (preflight before a run exists) skip the collision check rather than
       guessing — a speculative collision against a not-yet-existing run is noise.
       Resolution is write-free (plan 26-04), so preflight can call it as often as it likes.
    4. `_probe_openephys(host, port, config)` — the one OE-aware function. Calls
       `openephys_client.get_status`; a connection error propagates to the caller's guard;
       `decide_start(status)` returning False becomes `external_device_busy` with a detail naming
       the reported mode. **Never take over a device that is already recording**: the lease only
       knows about MICS-initiated runs, so a busy device may be a colleague's session; refusing is
       recoverable, taking over destroys data with no warning.
    5. Every issue dict follows the existing issue shape (`module_id`, `module_name`, `issue`,
       `detail`, plus kind-specific fields), matching `compute_lib_import_failed_issue()`'s
       precedent in `toolkit_dispatch.py`.

    Keep under 300 lines.
  </action>
