<objective>
Emit the three run-scoped faults: hardware that failed to instantiate (A1), a failed
`ExternalHardware` bind (A3), and which way the run ended (B1).

Purpose: the scan of `mics_core` found 49 swallowing exception handlers across the seven
critical-path files, and at several of them the run continues in a silently wrong state. Five are
approved. Two of them — the pilot-scoped pair — are already done in plan 08. These are the other
three.

The split is by scope, and scope decides the destination. Run-scoped means a run exists and the
failure is about *this experiment*, so it goes through `Event_Dispatcher.dispatch_event` to
ElasticSearch, the same path as `state_transition`, because it is part of the experimental record
and a post-hoc query must be able to say what the rig was actually doing.

**A1 belongs in both**, and that is the reason the badge exists: `Left_LED`/`Mid_LED` failed on
**every run** on pilot 3, and a per-run ES event alone never surfaced it — an audit did, weeks
later.

Output: three emitters, one teardown reordering that makes B1's event deliverable at all, and a
counted allowlist test.

<!-- Exact sites and the ordering problem that makes a naive B1 implementation emit nothing. -->

**A1 — `tasks/task.py:197-198`**, the last branch of `init_hardware()`'s per-pin loop:
`except Exception as e: self.logger.exception("Pin could not be instantiated - Type: {}, Pin: {}\nGot exception:{}".format(type, pin, e))`.
The loop then continues to the next pin, so the task runs with a missing actuator or sensor and
nothing upstream knows. In scope at that point: `type` (the group name), `pin` (the hardware id),
`hw_args`, `self.event_dispatcher` (constructed at `task.py:120`, i.e. **before**
`init_hardware()` runs — so it is available), `self.node`, `self.pilot`, `self.run_id`,
`self.subject`, `self.session`.

`Task` has **no** `self.parentid` — that attribute is `Pilot`'s. Use
`prefs.get('PARENTID') or 'T'`, matching how `Pilot.__init__` resolves it at lines 185/188.

**A3 — `tasks/mics_task.py:203-206`**, the post-pass in `mics_task.init_hardware()`:
`except Exception: self.logger.exception("init_hardware: ExternalHardware bind/lifecycle failed for %s", hw_id)`.
The extlink source never starts and the FDA silently gates on stale or default values. In scope:
`group`, `hw_id`, `hw`, and `hw.required`.

**B1 — `core/pilot.py`, four handlers, verified line numbers:**
- `982` `except StopIteration as e:` — the generator finished
- `1009` `except Exception as e:` — the task loop itself raised
- `1017` `except Exception: pass` — `event_dispatcher.stop()` raised
- `1021` `except Exception as e:` — `self.task.end()` raised
Which one fires **is** the crash reason.

**The ordering problem, and it is load-bearing.** The `finally` block today runs
`event_dispatcher.stop()` at line 1016 and `self.task.end()` at line 1020 — the dispatcher is
stopped BEFORE the task tears down. So (a) an ES event dispatched anywhere after line 1016 goes
nowhere, and (b) every hardware `release()` event that `@log_action` produces during `task.end()`
is already being lost today. Both are fixed by the same reordering: `task.end()` first, then the
`task_end` dispatch, then `event_dispatcher.stop()`.

Line `1017`'s own failure — the dispatcher refusing to stop — cannot by definition be reported
through the dispatcher. That one is **pilot-scoped** and uses plan 08's
`Pilot._report_pilot_fault`.

**`Event` / `Event_Dispatcher`:** `autopilot/utils/Events.py` `Event(event_type: str,
event_data: dict)` — both types are enforced with a `TypeError`. `event_data` must be a plain dict
of JSON-serialisable values. `Event_Dispatcher.dispatch_event(event, key='CONTINUOUS')` stamps the
clock and enqueues; it is run-scoped by construction (built with `subject`, `session`, `run_id`).

**FAULT-09's exclusions, which this plan must honour and prove:** `extract_task_metadata` (10
handlers), `discover_tasks_metadata` (2), `_coerce_hw_value` (2), `external/__init__.py:18,27`,
`get_name`, `_report_trigger_error:359`. B2 (`external_hardware_runtime.py`, 9 handlers) and B3
(`hardware/__init__.py:188`) are DEFERRED pending an overlap check. `Message` and `hardware_state`
are excluded from every sweep.
