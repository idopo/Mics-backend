      the `pulse(group_bits, group_mask, pulse_delay)` record type, `i2c_open`, `i2c_close`,
      `i2c_write_byte_data`, `i2c_read_byte_data`, `i2c_read_i2c_block_data`, the constants
      `RISING_EDGE FALLING_EDGE BOTH_EDGES SET_PULL_UP SET_PULL_DOWN SET_PULL_NONE TX_PWM TX_WAVE`,
      and `class error(Exception)`.
    - Every call is appended to a `.calls` list as `(name, args, kwargs)`, so a test can assert the
      exact `tx_wave` pulse list a production call produced.
    - **Edge injection — the single most load-bearing feature of this fake.** Every PLAT-27
      assertion downstream (`31-11` Task 2, `31-12` Tasks 2-3, `31-14` Task 2) is of the form
      "inject `ts_ns = 12345`, read `12345` back out of the payload". A fake that can record a
      registration but cannot fire it makes all of them unwritable, and plan 11 (wave 9) hits this
      first. So:
      - `callback(h, gpio, edge, func)` **records `func`** in a per-`(handle, gpio)` registration
        table alongside the `edge` mask it was registered for, and returns an object whose
        `.cancel()` **unregisters that one entry** (not the whole pin).
      - `fake_lgpio.fire_edge(handle, gpio, level, ts_ns)` invokes **every live registration** for
        that `(handle, gpio)` — in registration order — with lgpio's **4 positional** arguments
        `(chip, gpio, level, timestamp)`. `chip` is `handle >> 16`, matching
        `lgpio_extra.py:1127`; passing the packed handle straight through is the specific bug the
        `31-12` "inject chip handle 999, gpio 17, expect 17" test exists to catch.
      - `fire_edge` returns the number of registrations it invoked, so a test can assert
        **two** dispatch routes fired from one edge — see `31-12`'s `<scope_fence>` note on
        `Digital_Out.is_trigger = True`, which makes exactly that the normal case.
      - A registration cancelled with `.cancel()` is not invoked by a subsequent `fire_edge`;
        `fire_edge` on a pin with no registration returns 0 and does not raise.
      - `level == 2` (watchdog timeout) is injectable like any other level. The fake does not
        interpret levels; that is the port's job.
      - `fire_edge` records itself in `.calls` too, so a test can interleave assertions on
        commanded output and injected input in one timeline.
    - **The 4-argument contract is asserted, not assumed.** `tests/test_fake_lgpio_contract.py`
      registers a function capturing `*args, **kwargs`, calls `fire_edge`, and asserts
      `len(args) == 4 and kwargs == {}` and that `args[3]` is the injected `int` unchanged. If the
      fake ever hands over 3 args or a keyword, every downstream arity test becomes a tautology.
    - **Exceptions raised inside a fired callback propagate out of `fire_edge`** rather than being
      swallowed by the fake. Pitfall 8 is about the PRODUCTION code containing the exception; a fake
      that eats it would make `31-11`/`31-12`/`31-13`'s containment tests pass vacuously.
    - `gpio_get_chip_info` is driven by an injectable chip table, so one test can present the Pi 4
      layout (`pinctrl-bcm2711`, 58 lines), another the Pi 5 kernel-6.6.45 layout (`pinctrl-rp1` at
      index 0, 54 lines), another the kernel-6.12.96 layout (`pinctrl-rp1` at index 15).
    - Any function can be armed to raise `fake_lgpio.error`, so Pitfall 8 (an exception escaping a
      hardware callback) is testable.
    - A `fake_lgpio` pytest fixture installs the fake at `sys.modules['lgpio']` BEFORE the module
      under test is imported, and removes it on teardown.
