Phase 18 substrate this class consumes. **Read the SHIPPED `external_hardware.py` before writing —
Phase 18's final names may differ from its plans.** Do not reimplement any of it.
```python
class ExternalHardware(Hardware):
    def bind(self, ioloop, view): ...         # TWO args — see note below
    def on_run_start(self, run_ctx): ...      # returns truthy on success; retried in the wait window
    def on_run_stop(self): ...                # all Pi paths + backend safety net
    def release(self): ...                    # MANDATORY override; Task.end() always calls it
    liveness_hook = None                      # CLASS-LEVEL; `role: "none"` MUST override it
    _egress                                   # .enqueue(callable) — FIFO, fire-and-forget, no retry
```

**`bind` takes two arguments, `(ioloop, view)`.** An earlier draft of this plan recorded one.
`18-10-SUMMARY.md` is the authority — read it, not this block, if the two ever disagree.

**`role: "none"` requires a class-level `liveness_hook`, enforced by raising at construction**
(EXTLINK-18 as amended; Phase 18 plans 18-05/18-10). This is not optional and there is no default
that would let OpenEphys through: the base predicate is "a message arrived within `stale_ms`", which
a socketless module can never satisfy, so it would sit permanently `alive=False` and hang the
readiness gate with no diagnosis. Silently defaulting to `alive=True` was explicitly rejected — that
is exactly the "device is off but we think it's fine" failure OE's HTTP check exists to catch.

```python
liveness_hook(self, last_msg_ts_ms, now_ms, stale_ms) -> bool
```
Declare it as a **method on the class**. `validate_role_liveness` is handed
`getattr(type(self), "liveness_hook", None) is not None`, so a hook assigned on the INSTANCE in
`__init__` is invisible to it and the module raises at construction — it fails closed, but the error
is confusing. Phase 18 calls the predicate on a **per-device `LivenessPoller` daemon thread**, never
on the shared IOLoop, precisely so a blocking outbound HTTP call like OE's is safe there.

**`alive` has exactly one writer in the base class (`_recompute_alive`)**, composing the liveness
predicate with the egress failure counter. Never write the `alive` Tracker directly from this lib.
`run_ctx` is a single dict with six keys: `run_id`, `session_id`, `subject_key`, `pilot`,
task-definition id, start timestamp.

The readiness gate keys on **ready** (lib-defined), not merely `alive` — EXTLINK-13 as amended. For
OpenEphys "ready" means *recording has started*, so a box that is reachable but failed to enter
RECORD must fail the gate rather than pass it and silently record nothing.

Report-back channel (device-neutral; consumed by plan 26-11):
```python
self.event_dispatcher.node.send('T', key='ARTIFACT_PATH', value={
    "run_id": ..., "device_name": ..., "resolved_path": ...,
    "started_at": ...,
    "device_fields": {"experiment_number": N, "recording_number": M, "record_node_id": K},
})
```
`Event_Dispatcher` (`autopilot/networking/Event_Dispatcher.py`) holds `.node` and sends via
`node.send('T', key=..., value=...)`; `log_action` already relies on `self.event_dispatcher` being
present on a `Hardware` instance. **Verify both against the shipped code before relying on them**
and record any divergence in the summary.

Seeder precedent — `api/seed_compute.py`: copy the shape but NOT the `kind`. Use `kind='hardware'`
(Pitfall 5: `kind='compute'` would subject this to the stdlib-only import allowlist and the
compute-specific version-resolution rules, neither of which applies to a real hardware lib).

    - `__init__(self, host=None, port=oc.OE_DEFAULT_PORT, artifact_target=None,
      artifact_path_template=None, liveness_timeout_s=DEFAULT_LIVENESS_TIMEOUT_S, **kwargs)` —
      store the OE settings, pass the rest to `super().__init__(**kwargs)`. `init_hardware()` splats
      `pilot_hardware_config.config` in as kwargs, and plan 26-11 injects `artifact_target` into
      that same dict, so both arrive by one config path rather than two.

      **`liveness_timeout_s` MUST be an explicit keyword with a default here** — it is *not* part of
      Phase 18's config vocabulary (`18-10-PLAN.md` enumerates what the base absorbs, and this is
      not in it), so nothing upstream supplies it and nothing validates its absence the way Phase 18
      validates a missing `role`. The `pilot_hardware_config` row is hand-entered (Task 2), so an
      omitted or mistyped key would otherwise raise `AttributeError` inside `__init__` — which
      `init_hardware`'s per-module `except` swallows, leaving the task running with **no OE module
      at all**: no readiness gate entry, no recording, no artifact row, and nothing a researcher
      would see. Every automated gate in this phase would still pass, because the AST verify only
      checks method names and the class cannot be imported on the dev host; it would surface first
      at 26-13's single expensive rig session.

      Build the dedicated liveness client **after** `super().__init__(**kwargs)`, since it needs
      `self.stale_ms` for the invariant check. Assert
      `liveness_timeout_s < self.stale_ms / 2000.0` at construction and raise a `ValueError` naming
      both values if it fails — a bad hand-entered pair must fail loudly at startup rather than by
      silently stacking polls at runtime.

    - `on_run_start(run_ctx)` — returns True/False for the retried readiness contract:
      0. **Resume check, so a retry after a partial success is not fatal.** If `self._record_issued`
         is set and the box is currently in RECORD, skip straight to step 4 — that recording is
         MICS's own, from an earlier attempt this same run. Without this the hook is
         self-contradicting: step 3 puts the box into RECORD, so if step 3 or 4 fails, the retry
         re-enters at step 1, `decide_start` sees RECORD, and refuses **permanently** — the gate
         then times out and the box is only idled later by `release()`. `decide_start` is pure and
         stateless, so it cannot tell "a colleague's session" from "my own attempt 3 s ago"; only a
         flag on this instance can. "Never take over" is fully preserved for boxes MICS did not
         start, because the flag is only ever set by step 3 below.
      1. `status = oc.get_status(...)`; `may_start, reason = oc.decide_start(status)`. If not
         `may_start`: log the reason and return False. **Never take over a box already recording** —
         the lease cannot see someone using the OE GUI by hand, so a busy box may be a colleague's
         session. Issue no PUT at all on this path.
      2. `oc.set_recording(...)` with `oc.build_recording_config(...)` derived from
         `self.artifact_target`, plus `start_new_directory=True`. Only the six real fields.
      3. Set `self._record_issued = True` **immediately before** `oc.set_mode(host, port, "RECORD")`
         — before, not after, so a failure inside the call itself is still recoverable. Clear it in
         `on_run_stop`.
      4. **Read back**: `recording = oc.get_recording(...)` then
         `oc.resolved_path_from_recording(recording)`. Send `ARTIFACT_PATH` with the resolved
         path(s) and the read-back counters in `device_fields`. **Never predict a path** — a
         computed guess would record a location the data is not at, which is exactly what EPHYS-03
         exists to prevent.
      5. Emit the run-start marker, set the readiness flag, return True.
      Any exception → log and return False. The hook is retried inside the wait window, so a
      transient failure must be recoverable rather than fatal.

    - **`liveness_hook(self, last_msg_ts_ms, now_ms, stale_ms)` — MANDATORY, class-level.** Without
      it the module raises at construction, because its `pilot_hardware_config.config` carries
      `role: "none"` (see `<interfaces>`). **Never raise** — `LivenessPoller.poll_once` swallows and
      counts a raise as not-alive, but keep the contract explicit here. Ignore all three timestamp
      arguments: they exist for the data-arrival default, and a socketless device has no inbound
      messages to time. Put that reason in a comment so nobody later "fixes" the unused parameters.

      **The predicate is composite, not merely reachability**, because `26-CONTEXT.md` locks a
      second Bad-state decision this is the only mechanism for: *"Recording stops mid-run → log,
      flip `alive`, and surface prominently in pilot status."*

      **The decision itself lives in `oc.liveness_ok(status, run_active)` (plan 26-07), not here.**
      This method is only the I/O wrapper: call `oc.get_status(...)` inside a `try`, pass the dict
      (or `None` if it failed) plus "is a run active" — `on_run_start` has succeeded and the stop
      guard has not yet fired — into `oc.liveness_ok`, and return its answer. Keeping the rule in
      the `autopilot`-free client is what makes it agent-testable: this seeded lib imports
      `ExternalHardware` and therefore `autopilot`, so nothing in it can be unit-tested on the dev
      host. `26-02` pins the four cases.

      Outside a run, `run_active` is False and reachability alone is `alive`. That is what
      makes 26-13 step 4a's pre-run check correct (box powered on but IDLE reads `alive=true`), and
      it is consistent with Phase 18's "`alive` means REACHABLE, never data-fresh"
      (`18-10-PLAN.md:394`) — a recording that stopped is a *device* failure, not stale data. Log
      loudly on the transition and do NOT kill the behavioural session: EXTLINK-07 makes loss of
      liveness never automatically fatal, and the behavioural data stays valid.

      **The HTTP call MUST use a bounded client timeout, and there is a specific right way to get
      one.** `LivenessPoller.stop()` uses a bounded join, so a `get_status` blocked on an
      unreachable host with no timeout outlives `release()` — and the poller runs at
      `stale_ms / 2`, so an untimed call also stacks. Build ONE dedicated liveness client once in
      `__init__` via `oc.make_client(timeout_s=self.liveness_timeout_s)` (plan 26-07 ships the
      factory) and pass it on every poll. Do **not** fall back to `DEFAULT_TIMEOUT_S = 5.0`: that is
      the module-wide default for lifecycle calls, and at the canonical `stale_ms: 3000` it is 3.3×
      the 1.5 s poll interval — exactly the stacking this paragraph warns about. Task 2's documented
      config shape therefore pins `stale_ms` and `liveness_timeout_s` together with a stated
      relationship, rather than leaving the poll rate implicit.

    - **`is_ready()`** — Phase 18 pins this name (`18-10-PLAN.md:400`); it defaults to the current
      `alive` value, and this lib overrides it to return the flag set in `on_run_start` step 5.
      Confirm the name against the shipped base class before writing, since `18-10-SUMMARY.md`'s
      mandatory contract list does not currently include it. **Readiness is NOT liveness and the two must
      not be conflated here.** `liveness_hook` answers "is the box reachable"; readiness answers
      "has recording started". A box that is reachable but failed to enter RECORD is `alive=True`
      and NOT ready — it must fail the gate, which is the entire reason EXTLINK-13 was amended from
      *alive* to *ready*. Reachability alone is not readiness.

    - `on_run_stop()` — **check-and-set the "already stopped" guard at the very TOP of the method**,
      before the marker and before the IDLE call. Then emit the run-stop marker **first**, then
      `oc.set_mode(host, port, "IDLE")`. Order matters twice over:
      - A stop marker sent after IDLE lands outside the recording and is worthless.
      - The guard is what makes `run_active` False, and the `LivenessPoller` daemon thread is
        **still polling** throughout teardown — it is only stopped in `release()`. If the guard were
        set at the END of the method, then between the IDLE PUT and the flag flip the poller would
        observe `run_active=True` with the box IDLE, flip `alive=false`, and fire the "recording
        stopped mid-run" CONTINUOUS event plus its prominent status alarm **on every clean run
        end**. At `stale_ms: 6000` the poll is every 3 s, so that window is routinely hit. An alarm
        that cries wolf on every normal stop trains researchers to ignore the one that matters,
        which defeats the locked decision the composite predicate exists to serve.

      Clear `self._record_issued` here too, so a subsequent run starts from a clean resume state.
      Idempotent: it runs on normal completion, STOP, task exception, and possibly again from the
      backend safety net. Never raise.

    - `release()` — **mandatory override**. Call `on_run_stop()` under the same guard, then the
      base's `release()` if one exists. The `Hardware` base raises when `release` is not overridden,
      and `Task.end()` calls it unconditionally on every hardware object on every run, inside an
      untried loop — an exception here takes down teardown.

    - `send_marker(self, label, run=None, trial=None)` decorated with `@log_action`. The body builds
      `text = oc.marker_text(label, run, trial)`, calls
      `self._egress.enqueue(lambda: oc.send_message(self.host, self.port, text))`, and returns
      `text`. That is all it does. `@log_action` captures the call synchronously on the FDA thread
      the instant it runs — that is the dual-log, it survives total network failure, and it is what
      Phase 28 diffs against. The enqueue is what keeps the FDA thread unblocked.
      **Markers ride Phase 24's existing `hardware` action type — add no new action type.**

    - **No automatic trial markers.** Do not reference `INC_TRIAL_COUNTER` anywhere. Auto trial
      markers were explicitly rejected: a task that does not send the counter would silently produce
      no markers and present as an ephys bug rather than a task bug.

    - A mid-run loss of recording → log loudly and flip `alive` **via `liveness_hook`'s condition 2
      above** — that composite predicate IS the mechanism, and it is the only one, since the base
      class owns the `alive` Tracker through `_recompute_alive` and this lib must never write it
      directly. Do NOT kill the behavioural session; the behavioural data stays valid and the
      researcher decides whether to stop.
