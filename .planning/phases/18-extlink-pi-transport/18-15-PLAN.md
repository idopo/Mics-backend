<constraints>
**Location: `mics-backend/tools/extlink_driver/`. NOT `~/pi-mirror/`.** The mirror is rsynced to
the Pi; a macOS tool must never land in that payload. `tools/` does not exist yet — create it.

**Cross-platform is a hard requirement, not an aspiration.** macOS now, Windows later, the same
file unchanged. Therefore: `pyzmq` + `msgpack` and stdlib only; no `termios`, no `curses`, no
`select` on stdin, no `signal.SIGALRM`, no `os.fork`, no POSIX path assumptions, no ANSI escape
sequences beyond plain text. Read input with plain blocking `input()` in the main thread. The three
modes (interactive / `--sweep` / `--rate`) are **mutually exclusive**, which removes the only
reason threading would have been needed.

**The Python 3.7.3 pin from plan 18-04 is a RIG constraint and does NOT bind this file** — it runs
on the researcher's laptop, where a current Python is fine. What DOES bind is the wire format:
frames this tool emits must be decodable by the Pi's 3.7-era `msgpack`. Use only plain
dict/str/int/float/bool payloads; no ExtType, no custom `default=` hooks, no
`datetime` auto-packing.

**No ack handling and no latency measurement in v1** — a deliberate deferral, not an omission.
Comparing a laptop send-timestamp against the Pi's `ts_pi_recv` measures clock skew, not latency;
those machines are not NTP-synced to each other. That measurement belongs to Phase 28 (TTL vs
Network Sync Validation). Put that sentence in the README so the next person does not add a
`--measure-latency` flag that lies.

**`role: router_bind` only.** The Pi binds its ROUTER, this tool dials in as a DEALER with
`identity = source_id`, so the laptop's IP never appears in any `pilot_hardware_config` row and a
DHCP or Wi-Fi change cannot break the setup. `sub_connect` is proven separately by 18-12's Lib C
and is explicitly out of scope here.

**Dev-host reality (18-VALIDATION.md):** `zmq` is absent from the dev host and `msgpack` is
installed agent-side by plan 18-01. So every automated verify in this plan must run without a
socket, and `--help` must work on a machine with no `zmq` (do the `zmq` import inside the mode
handlers, the same trick plan 18-11 Task 3 used for `extlink_smoke.py`).

**Pi rules are absolute:** this plan runs nothing on the Pi, deploys nothing, restarts nothing, and
runs no git against the Pi or against `/home/ido/pi-mirror`. It only READS the mirror by path in a
test.

  <files>tools/extlink_driver/extlink_driver.py</files>
  <action>
    Create `tools/extlink_driver/extlink_driver.py`. `argparse`, three mutually exclusive modes,
    common args `--pi-host` (required), `--listen-port` (required), `--source-id` (required).

    - **interactive (default)** — print the connection line and a one-line usage reminder, then
      loop on `input("> ")`. Each line goes through `parse_command`; a parsed command is packed and
      sent immediately and echoed back as `sent SIG left_paw_x = 0.7 (seq 12)` so the user can
      correlate what they typed with what the rig shows. An unparseable line prints a hint and
      reprompts. `EOFError` (Ctrl-D / Ctrl-Z) and `KeyboardInterrupt` both exit cleanly, closing
      the socket and the context.
    - **`--sweep SIGNAL`** — hands-free auto-ramp, with `--min` (default 0.0), `--max`
      (default 1.0), `--sweep-hz` (default 5) and `--seconds` (default 60). Ramps up then down and
      repeats, so a threshold at any value inside the range is crossed in both directions. This is
      how the user sees a transition fire and un-fire without touching the keyboard.
    - **`--rate N`** — the soak driver: send `--signal` at N Hz for `--seconds` (default 30),
      printing a progress line about once a second with the count sent. **This is a soak, not a
      benchmark.** Print no latency number and compute no statistics; the pass/fail lives on the
      rig side (pilot stays up, FDA keeps transitioning, bounded queues report their drops, ES
      keeps up). Say that in `--help`.

    **Import `zmq` and `msgpack` inside the mode handlers, never at module scope**, so `--help`
    works on a machine that has neither. Print an actionable message on `ImportError`:
    `pip install pyzmq msgpack`.

    `seq` is a single monotonically increasing counter across the whole process lifetime, shared by
    all three modes — the Pi's ingress uses it for ordering diagnostics, and a per-mode counter
