<decisions>
## Decisions locked by this plan

1. **The driver imports `mics_link.wire`, NOT `mics_link.MicsLink`.** The client's bounded async
   queue would change the driver's synchronous per-line semantics — today `sock.send(frame)` is
   followed immediately by `print("sent ...")`, and an async queue would make that print a lie the
   moment the queue backed up. SDK-10 requires the driver's CLI surface be **behaviourally
   unchanged**; swapping in the async client is not that. The driver keeps its own `zmq` socket and
   its own `seq` int. It "imports the SDK" in the sense SDK-10 means: it no longer carries its own
   copy of the protocol.

2. **`parse_command` moves to a new `tools/extlink_driver/extlink_cli.py`; it does NOT go into the
   SDK.** CONTEXT.md is explicit: `coerce_value` and `parse_command` are driver CLI concerns, not
   SDK concerns — the SDK takes typed Python values, so parsing a stdin token belongs with the
   driver. The generic half (`coerce_value`) DID move, as `mics_link.values.coerce_token`; the
   `"a dict token means EVT"` rule stays here because it is a property of this CLI, not of the
   wire.

3. **Lazy import is preserved.** `python3 tools/extlink_driver/extlink_driver.py --help` must keep
   working on a laptop with nothing installed. `_import_wire()` therefore imports `mics_link.wire`
   inside the function body and `sys.exit`s with an install hint on `ImportError` — the hint text
   changes from `pip install pyzmq msgpack` to the SDK install line (decision 4).

4. **The driver's distribution story changes and the README must say so.** Today the driver reaches
   laptops as a hand-copied bundle (`extlink_driver_mac.zip` at the repo root) with
   `extlink_wire.py` as a sibling. Once it imports `mics_link`, a laptop running the driver must
   have the SDK installed. The README's Install section becomes:

       pip install "git+https://github.com/idopo/Mics-backend.git#subdirectory=sdk"

   with the note that this replaces the old `pip install pyzmq msgpack` (the SDK pulls both in).
   **Retiring or refreshing the zip itself is explicitly deferred** (CONTEXT.md `<deferred>`); this
   plan's only obligation is to not reintroduce a second wire copy through it. Add one sentence to
   the README saying the zip is stale until that decision is made.

5. **`test_extlink_wire.py` keeps its filename** even though the module it was named after is gone.
   Renaming it would obscure the git history of the one file that documents this envelope's
   contract. Update its docstring to say what it now tests and why the name persists.

6. **The stale comment must go.** `test_extlink_wire.py`'s docstring claims *"`zmq` is absent from
   this dev host"*. That is false — pyzmq 27.1.0 is installed (34-RESEARCH.md). Do not repeat the
   false claim while retargeting; the socketless requirement stands on its own merit (the RIG is
   what is unavailable), so restate it correctly.
</decisions>
