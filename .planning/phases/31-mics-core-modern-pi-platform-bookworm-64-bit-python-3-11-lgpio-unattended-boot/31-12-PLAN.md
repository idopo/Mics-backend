<objective>
Stage 3, part 2. Port the **input** half of `gpio.py`: pin claiming, pull configuration, edge
alerts, callbacks and debounce — and, with them, the **single-clock invariant (PLAT-27)**.

Purpose: this is the half where lgpio is unambiguously better, and it is where the phase's central
24/7 claim is actually earned. Today an edge arrives as a pigpio daemon **tick** — a 32-bit
microsecond counter living in another process's clock domain, mapped into wall time by a
Cristian's-algorithm round-trip estimator that goes stale after any clock step and re-syncs only on
wrap. After this plan, an edge arrives with the kernel's own timestamp, taken in **hardirq
context** (`gpiolib-cdev.c edge_irq_handler()`: *"Just store the timestamp in hardirq context so we
get it as close in time as possible to the actual event"*), on `CLOCK_MONOTONIC`, as 64-bit
nanoseconds.

**Input before output is deliberate.** The loopback harness measures widths through the *input*
path, so the input port has to be right before any output measurement means anything. Getting these
the wrong way round would produce output numbers contaminated by an unported input path.

**PLAT-27 is here and not in plan 14, deliberately.** `assign_cb` is the registration seam
(`task.py:199`), it lives in `gpio.py`, and porting the callback to lgpio *is* what changes its
arity — so the adapter cannot be deferred without shipping a broken callback path for a whole wave.
The same argument applies one step further: the moment the third callback argument stops being an
ISO string, `localize_tz` (`utils/common.py:329`) raises inside `execute_trigger`, in a code path no
test in this plan would otherwise touch. So this plan also creates the **one** epoch offset — a
single `autopilot/utils/clock.py` — and wires the `pi_timestamp` path to it. Plan 14 **imports that
same module** for the dispatcher; it does not compute a second offset, and it carries the
cross-path "same instant" regression test, which cannot exist until the dispatcher half is ported.

Output: `gpio.py`'s input classes on lgpio, a single tree-wide clock conversion, and the edge
timestamp threaded to the boundary where plan 14 picks it up.
</objective>

<verified_port_facts>
**Migration map (verified against lgpio 0.2.2's shipped Python API):**
| pigpio (in the tree today) | lgpio | Quality |
|---|---|---|
| `pi.set_mode(p, INPUT/OUTPUT)` | `gpio_claim_input` / `gpio_claim_output` | Full |
| `pi.set_pull_up_down(p, PUD_*)` | `lFlags=SET_PULL_UP / SET_PULL_DOWN / SET_PULL_NONE` on the claim | Full |
| `pi.read` / `pi.write` | `gpio_read` / `gpio_write` | Full |
| `pi.callback(p, EITHER_EDGE, f)` | `gpio_claim_alert(h, p, BOTH_EDGES, lFlags)` **then** `callback(h, p, BOTH_EDGES, f)` | Full, and better — the timestamp is kernel-at-interrupt rather than a daemon tick |
| `pi.set_glitch_filter(p, us)` | `gpio_set_debounce_micros(h, p, us)` | Full, with the timestamp-shift caveat |
| `pi.set_pad_strength` / `get_pad_strength` | — | **None.** Delete. |
| `pi.gpio_trigger(p, us, level)` | `tx_wave` two-pulse, or `gpio_write` x2 | Full — but if the call site is an OUTPUT, it belongs to plan 13 |

**Callback signature:** `callback(handle, gpio, edge=RISING_EDGE, func=None)` returns a callback
object with `.cancel()`. The function receives `(chip, gpio, level, timestamp)` where `level` is
0 falling, 1 rising, **2 watchdog timeout** — handle level 2 explicitly rather than treating it as
an edge.

**Two things that are easy to get wrong:**
1. `callback()` does **not** claim the line. `gpio_claim_alert()` must be called first, or the
   callback never fires — silently.
2. `callback()` takes `handle >> 16` internally (`lgpio_extra.py:1127`) because `gpiochip_open`
   packs the chip number into the handle's high bits. Pass the handle from `gpiochip_open`
   unmodified and it works. **Never construct a handle by hand.**

**The notification FIFO (PLAT-10).** `import lgpio` opens `<workdir>/.lgd-nfy<N>` — a RELATIVE
path — and starts a daemon thread **at module import time** (`lgpio_extra.py:273, :331`).
`gpio_claim_alert(..., notify_handle=None)` wires into it automatically. The systemd unit's
`LG_WD` + `RuntimeDirectory` is what makes this work; `31-SPIKE.md` should record that
`.lgd-nfy*` was observed. **Also note `lguGetWorkDir()` calls `chdir()` on the whole process when
`LG_WD` is set** — so do not add any relative-path assumption in this code.

**Debounce timestamp shift (Pitfall 3).** `gpio_set_debounce_micros` deliberately timestamps a
debounced event `debounce` microseconds AFTER the physical edge — stated in the docstring
(`lgpio_extra.py:1000-1001`) and implemented at `lgPthAlerts.c:322`. pigpio's glitch filter did
not. Plan 11 already chose a policy for `i2c.py`'s IRQ lines; **use the same policy here** and
cross-reference it, so the tree does not carry two conventions.

**Do not read a clock inside the callback.** The `ts_ns` argument IS the edge time; anything read
inside the callback includes the full ppoll + FIFO + Python-dispatch latency (lgpio's alert thread
polls with a 0.5 ms `ppoll` timeout, `lgPthAlerts.c:438`). This is the single change that makes the
kernel-timestamp claim visible in the data — the current code discards it
(`Event_Dispatcher.py:77` calls `self.pi.get_current_tick()` in the calling thread). Thread `ts_ns`
outward to the class boundary here; plan 14 connects it to the dispatcher.

**Error containment (Pitfall 8).** Same rule as plan 11: wrap every lgpio call reachable from a
callback in `try/except lgpio.error`, count, never propagate, never set
`lgpio.exceptions = False` globally.

**Chardev line ownership (Pitfall 4).** Lines are released when the process dies, so the pin
reverts to its default state — unlike pigpio, whose daemon outlived the client and kept driving.
For inputs this is harmless. It matters on the reward path and is verified physically in plan 16.
</verified_port_facts>

<single_clock_invariant>
## PLAT-27 — read `CONTEXT.md` §13 before writing any of Task 3. Do not re-derive it.

§13 is a verified audit of the live rig's own `site-packages/pigpio.py`. The short version, and the
three things that break if this is left unowned:

**How it works today.** The Autopilot-patched pigpio converts tick → timestamp **inside its
notification thread**, before any callback fires (rig `pigpio.py:1239-1240`). So every `assign_cb`
callback receives an **ISO-formatted string**, not a raw tick. The path is:

```
Digital_In.assign_cb (gpio.py:879)
  -> self.pig.callback(pin, edge, callback_fn)
    -> Task.handle_trigger  (registered at task.py:199 via partial(..., hardware=hw))
      -> Task.execute_trigger (task.py:269)
        -> localize_tz(tick)                       (utils/common.py:329-334)
        -> event_data = {"id": ..., "pi_timestamp": tick}   (task.py:276)
```

`Event_Dispatcher` reads the **same** `_sync_offset` via `ticks_to_timestamp(..., isoformat=False)`.
One clock, two representations: ISO string on the callback path, float on the dispatcher path.

**It already degrades, which is the argument for the port, not against it.** The callback thread's
copy of the offset is a **scalar snapshot** passed by value at `pigpio.py:1157`. When
`ticks_to_timestamp` detects a wrap and re-runs `synchronize()`, it updates `pi._sync_offset` and
**never propagates it to the running callback thread** — so after the first 71.6-minute wrap (~20×
a day under 24/7) the two paths drift apart. On `OverflowError` the callback thread sets
`self.synchronize = None` and silently reverts to raw ticks, at which point `localize_tz`'s
`strptime` receives an int and raises.

**What must be true after this plan:**

1. **`assign_cb` keeps its signature and its 3-argument callback contract.** It is the seam
   `task.py:199` uses to wire every trigger; changing it ripples through the whole task layer. The
   adapter that absorbs lgpio's 4-arg `(chip, gpio, level, timestamp)` down to `(gpio, level, ts)`
   lives **inside `assign_cb`**, because that is where the conversion site moved to: lgpio has no
   notification thread to do it for us.
2. **One epoch offset, in one module, read by both paths.** `autopilot/utils/clock.py` is the only
   place in the tree that reads `CLOCK_REALTIME`. `localize_tz` uses it; plan 14's
   `Event_Dispatcher` imports the same function. **No second offset. No cached scalar copy** — the
   cached copy *is* the defect described above. "Computed once" means one implementation, not one
   evaluation: the conversion recomputes the REALTIME↔MONOTONIC relation per call (two vDSO reads,
   tens of nanoseconds), which is the only form that stays correct across a wall-clock step.
3. **`localize_tz`'s input contract changes deliberately and is tested.** It now takes kernel
   monotonic nanoseconds. A stale caller passing a string must fail **loudly** with a message that
   names the change, not silently produce a plausible-looking wrong answer.
4. **The mandatory cross-path regression test** — one injected edge producing a `pi_timestamp` and a
   dispatcher timestamp that refer to the same instant — lands in **plan 14 Task 2**, because the
   dispatcher half is not ported until then. Do not stub it here. What this plan owes plan 14 is the
   raw `pi_timestamp_mono_ns` on the event, so the assertion has two comparable values.

**Compatibility with the protected guard test.** `tests/test_execute_trigger_guard.py` is in the
protected manifest and calls `execute_trigger` with `hardware=None` (verified 2026-08-17). The
`localize_tz` call sits inside `if hardware and isinstance(hardware, Hardware):`, so the protected
test never reaches it. It must keep passing **unmodified**; if it does not, the change went outside
this fence.

**Two `assign_cb`/`record_event` pairs exist, not one** (verified by direct `grep -n`):
`Digital_Out` at `gpio.py:380`/`:428` and `Digital_In` at `gpio.py:879`/`:939`, plus the abstract
`Hardware.assign_cb` at `hardware/__init__.py:166`. Port **all three**. A half-ported pair is
exactly the silent failure this requirement exists to prevent.
</single_clock_invariant>
