## DEFECT B — the cross-clock subtraction. VERIFIED IN SOURCE. Not the reason the override exists.

**When:** 2026-08-24, Phase 31 Plan 10, `mics_core` only. Current on pilot 3.
Five readings, which the executor MUST re-confirm before acting on them:

1. `mics_core/autopilot/autopilot/hardware/external_hardware_binding.py` `_now_ms()` returns
   `int(time.time() * 1000)`, and its comment says it is *"deliberately NOT converted through the
   one clock"* and claims *"Phase 31 Plan 10's F7 exempts this site by name"*.
   **That claim is FALSE, and the finding must say so (D-49).** Verified against the shipped guard,
   `mics_core/tools/tree_integrity/final_checks.py`: `F7_CLOSURE` is nine files and
   `external_hardware_binding.py` is NOT among them, and `F7_EXEMPTIONS` has exactly ONE entry —
   the *ingress* `ClockNotReady`/`ClockFault` fallback, not binding's `_now_ms()`. Being OUTSIDE a
   closure is not the same as being EXEMPTED BY NAME: the first means unexamined, the second means
   examined and permitted. **Cite this comment as a claim that was checked and found inaccurate,
   never as design rationale.**
2. `_liveness_tick(owner, pred)` in the same file calls `pred(owner._last_msg_ts_ms, now_ms, owner.stale_ms)`
   with that `time.time()`-derived `now_ms`.
3. `external_hardware_wire.default_liveness(last_msg_ts_ms, now_ms, stale_ms)` returns
   `(now_ms - last_msg_ts_ms) < stale_ms` — a bare subtraction of the two.
4. `mics_core/.../external_hardware_ingress.py` `on_recv` sets `owner._last_msg_ts_ms = ts_ms`
   where `ts_ms` comes from `_now_ms_and_mono_ns()`: `clock.now_from_tick()` (the pigpio-tick
   fitted mapping) converted by `MicsClock.to_utc_ns`. That is the ONE CLOCK, not `time.time()`.
5. `pi-mirror/.../external_hardware_ingress.py` stamps `int(time.time() * 1000)` instead.

So on the `mics_core` stack, `now_ms` (system wall clock) is subtracted from `last_msg_ts_ms`
(pigpio-tick-derived), and the difference includes whatever offset the fitted tick mapping carries at
that moment. If that offset exceeds `stale_ms` (3000 ms for the demo fixture) the device reads dead
forever while frames are arriving; if it is negative and large it reads alive forever. On `pi-mirror`
both sides are `time.time()` and B cannot occur.

**One caveat on B's own mechanism:** `_now_ms_and_mono_ns` falls back to `int(time.time() * 1000)` on
`ClockNotReady`/`ClockFault` and counts the fallback. A pilot in permanent fallback has both sides on
`time.time()` again, so B predicts NO failure there — check the fallback counter before concluding
that B is or is not active on a given run.

## This is a Phase 31 DEFECT for B, not a sanctioned carve-out (D-49/D-50/D-51)

The framing matters more than it looks, because it decides who owns the fix and whether anyone ever
makes it. Three things to state in the finding:

**The subtraction violates the one-clock invariant; it is not an exception to it.** The invariant
WAS the intent — that is exactly why a cross-clock subtraction is a violation of it rather than a
carve-out from it. Recording this as "a documented exemption" would make a bug look like a design.

**Phase 31 Plan 10 introduced it (D-50).** Commit
`1f35782 feat(31-10): every remaining record timestamp onto the one clock (Task 2)` moved **ingress**
onto the one clock. The same plan's Task 2 item 7 said of binding: *"change nothing... it is
liveness bookkeeping, not a record timestamp."* That reasoning is **true of the value in isolation
and false in composition**: binding's wall-clock `_now_ms()` is subtracted from `_last_msg_ts_ms`,
which that very plan had just moved onto the one clock. One plan converted one side of a subtraction
and deliberately left the other. Neither decision is wrong alone; together they are the bug.

**F7 structurally cannot catch this class of defect (D-51), and the eventual fixer must know that.**
Two independent reasons: `binding.py` is outside `F7_CLOSURE` so the file is never scanned; and F7 is
an AST walk over `ast.Call` nodes matching forbidden call FORMS, which has no notion of two values
being differenced. A guard that asks *"does this file read the wall clock?"* cannot see *"these two
clocks meet."* So **adding `binding.py` to `F7_CLOSURE` would catch the call and still not catch the
composition** — say that explicitly, because it is the obvious fix and it is insufficient on its own.

**How both errors were surfaced:** the user challenged the "F7 exempts it by name" claim, and then
the dates were checked and refuted the causal story linking the override to the clock bug. Neither
survived contact with the evidence. Record both, because they are why the finding is trustworthy now
and a standing reminder that an in-source comment asserting its own authority is a claim, not a
citation — and that a plausible mechanism is not a cause until the timeline agrees.

## THE FIX, and what it does and does not fix

**The permitted fix here is lib-level, never substrate-level — and it is a WORKAROUND, not a
resolution.** A `liveness_hook` override that reads the CURRENT time from the same source the
ingress stamp came from restores a like-for-like comparison without touching a single Pi file.
`make_liveness` (external_hardware_wire.py:170-173) REPLACES the default with the override, so the
hook owns the decision completely. DLC-01 forbids this phase from editing the substrate, so a
workaround is the correct move — but it must be labelled one, with Defect B left open and OWNED BY
PHASE 31/18, not absorbed as normal.

**It fixes B. It may not fix A.** A hook that compares like-for-like removes the clock-domain
mismatch and nothing else. If Defect A is the egress probe, or a startup race, or something not yet
enumerated, this hook does not touch it. **So the quiet test in plan 35-09 passing is NOT
guaranteed, and its failing is not a failure of this plan** — it is Defect A resurfacing, which is
the single most valuable thing this phase could learn about the substrate.
