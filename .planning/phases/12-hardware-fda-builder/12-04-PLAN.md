# Phase 12, Plan 4: Initial State Selection for Sourceless Toolkits

**Requirement:** HW-21  
**Phase goal:** Let users mark the initial state of a UI-built FDA (sourceless toolkit). Source-based toolkits got this for free (`prepare_session` was always first); sourceless toolkits need an explicit mechanism.

**Scope:** UI-only. Pi already enforces `initial_state` correctly. No API or DB changes needed.

**Gate:** Requires Phase 12-03 (FDA builder exists with StateNode + TaskEditor).

---

## Context

`StateNode.tsx` already renders an `INIT` badge and removes the target Handle for the initial state.  
`fdaToNodes()` sets `isInitial: name === fdaJson.initial_state` when loading from saved JSON.  
`bootstrapFromToolkit()` sets `initial_state: toolkit.states[0]` — only works for source-based toolkits.  
`addState()` always hardcodes `isInitial: false` and never updates `fdaJson.initial_state`.

So the gap is purely about how the user sets / changes `initial_state` in the UI when building from scratch.

## Fix 1: Auto-set initial state when first state is added

**File:** `web_ui/react-src/src/pages/task-editor/TaskEditor.tsx` — `addState()` (~line 283)

When the FDA has no states yet (or `initial_state` is unset), the first added state should become
the initial state automatically:

```typescript
const addState = () => {
  const name = newStateName.trim()
  if (!name || !fdaJson) return
  if (fdaJson.states[name]) { setNewStateName(''); setAddingState(false); return }

  const existingCount = Object.keys(fdaJson.states).length
  const isFirst = existingCount === 0 || !fdaJson.initial_state

  setFdaJson(prev => {
    if (!prev) return prev
    return {
      ...prev,
      states: { ...prev.states, [name]: {} },
      initial_state: isFirst ? name : prev.initial_state,
    }
  })
  setNodes(prev => [
    ...prev.map(n => isFirst ? { ...n, data: { ...n.data, isInitial: false } } : n),
    {
      id: name,
      type: 'stateNode',
      position: { x: (existingCount % 4) * 270, y: Math.floor(existingCount / 4) * 170 },
      data: { name, state: {}, isInitial: isFirst, toolkit },
    },
  ])
  setNewStateName('')
  setAddingState(false)
  setSelectedState(name)
}
```

## Fix 2: "Set as Initial" right-click context menu on state nodes

### 2a: Context menu state in TaskEditor

Add state for a pending context menu:

```typescript
const [ctxMenu, setCtxMenu] = useState<{ nodeId: string; x: number; y: number } | null>(null)
```

Wire `onNodeContextMenu` on the `<ReactFlow>` component:

```typescript
onNodeContextMenu={(e, node) => {
  e.preventDefault()
  setCtxMenu({ nodeId: node.id, x: e.clientX, y: e.clientY })
}}
onClick={() => setCtxMenu(null)}
```

Render a small absolute-positioned menu when `ctxMenu` is set:

```tsx
{ctxMenu && (
  <div
    style={{
      position: 'fixed', top: ctxMenu.y, left: ctxMenu.x,
      background: 'var(--panel)', border: '1px solid var(--border)',
      borderRadius: 6, padding: '4px 0', zIndex: 1000,

    onMouseLeave={() => setCtxMenu(null)}

    <button
      style={{ display: 'block', width: '100%', padding: '6px 14px',
               background: 'none', border: 'none', color: 'var(--text)',
               cursor: 'pointer', textAlign: 'left', fontSize: 13 }}
      onClick={() => { setInitialState(ctxMenu.nodeId); setCtxMenu(null) }}
    >
      Set as Initial State
    </button>

```

### 2b: `setInitialState` handler

```typescript
const setInitialState = (stateName: string) => {
  setFdaJson(prev => prev ? { ...prev, initial_state: stateName } : prev)
  setNodes(prev => prev.map(n => ({
    ...n,
    data: { ...n.data, isInitial: n.id === stateName },
  })))
}
```

This updates both `fdaJson.initial_state` (so it round-trips through auto-save and save mutation)
and all nodes' `isInitial` so `StateNode` renders the INIT badge + no target Handle immediately
without waiting for a full canvas re-sync.

## Fix 3: Handle deletion of the initial state

**File:** `TaskEditor.tsx` — `deleteState()` handler (wherever it exists; search for state deletion logic)

When the deleted state was the initial state, clear `fdaJson.initial_state` to empty string:

```typescript
const deleteState = (stateName: string) => {
  setFdaJson(prev => {
    if (!prev) return prev
    const { [stateName]: _dropped, ...remainingStates } = prev.states
    return {
      ...prev,
      states: remainingStates,
      initial_state: prev.initial_state === stateName ? '' : prev.initial_state,
    }
  })
  setNodes(prev => prev.filter(n => n.id !== stateName))
  // also remove any transitions involving this state
  setEdges(prev => prev.filter(e => e.source !== stateName && e.target !== stateName))
  setFdaJson(prev => prev ? {
    ...prev,
    transitions: prev.transitions.filter(t => t.from !== stateName && t.to !== stateName),
  } : prev)
  if (selectedState === stateName) setSelectedState(null)
}
```

## Fix 4: Validation warning when initial_state is unset

**File:** `TaskEditor.tsx` — save mutation or save button area

Add a derived boolean and a warning message:

```typescript
const hasStates = Object.keys(fdaJson?.states ?? {}).length > 0
const missingInitial = hasStates && !fdaJson?.initial_state
```

Show inline warning near the Save button:

```tsx
{missingInitial && (
  <span style={{ color: '#f87171', fontSize: 12, marginRight: 8 }}>
    No initial state set — right-click a state to set one
  </span>
)}
```

Block the save mutation when `missingInitial` is true (return early before calling API):

```typescript
const handleSave = () => {
  if (missingInitial) return
  saveMutation.mutate()
}
```
